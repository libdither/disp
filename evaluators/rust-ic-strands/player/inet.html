An interaction net of raw trees

Every agent is a leaf, a stem or a fork, save the walker (blue) and the root it hangs from. The program, the tree it works on and the walker's stack are all such trees; the colour says only which one an agent began in. A shape's point is its principal port.

Each step is one meeting of the walker with the agent its principal port faces (lit gold), and rewires only their ports. Nothing carries a label: what happens is the shape met.

The program is read by shape. A leaf: nothing. A fork: its left part, then its right. A stem: a step, named by the small tree under it (swap, rotate, add or drop a leaf or stem, take a part out or put it back, choose, call). Going down into a node turns its point toward the walker; coming back up turns it again, so the path is kept in the nodes.

Steps on the tree take one to three meetings, an agent at a time, held in the walker's two hands. A choice reads its path, goes down the tree to read one shape and takes that arm. A call copies the definition's number as stems, climbs to the root leaving a frame at each node it climbs out of, counts its way along the library and, done, follows the frames back.

The layout is a force between agents: wires pull, agents push apart. What the walker holds is pulled toward it.

One walker, one meeting at a time. A second walker could not share the program: in a net a node is only reached through its point, so reading a node means turning it toward you, and the whole path from the root is turned toward the one walker on it. Walkers working at once would each need their own copy of the code they read (the tree calculus's net copies everything, and so runs wide). ◀ replays from the start for now.
