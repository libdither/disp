01 / The organizing idea

One universe.
Several different jobs.

The closest precedent is Patrick Cousot’s Types as Abstract Interpretations: derive type information from the semantics of an untyped language. Scott’s universal domains and PER models supply two other pieces.

The strong version of the idea is general semantics + partial evidence procedures + certified abstractions + certified transformations. These parts can cooperate without all being the same construction.

α ⊣ γ

Forget, soundly.

An abstraction retains enough information to answer a question. A genuine adjunction specifies the best approximation expressible in that abstraction.

n² = n

Choose representatives.

A normalizer can select a canonical part of a universal space. Idempotence gives a retraction; an order adjunction needs more structure.

p ≃ p′

Change the execution.

An optimization preserves the observations you care about. Whether it is faster is a separate claim, with a separate cost model.

The three closest foundations: Cousot on types as abstractions · Scott on retracts of a universal domain · PERs and realizability. The unifying architecture is a synthesis of these ideas, not an established theorem equating every type system.

    universal properties.

    For dependent types, retain the family structure. In suitable categories of families, this becomes Σf ⊣ f* ⊣ Πf. A telescope composes contexts. Its fibers must respect equality and substitution; when values change context, transport may be required.

    Lawvere’s quantifiers-as-adjoints construction is the foundation. The finite predicate experiment displays the poset version; it does not model all the proof data of dependent type theory.

    06 / Experiment four

    A search strategy
    is not a truth oracle.

    To check a universal claim, give each input a task. Some return evidence, some loop. Fair scheduling can stop one task from starving the rest. It cannot make an unfinished universal claim true or false.

    Try three contrasts. A serial search gets stuck on T1 in the first scenario; a fair search reaches T2’s counterexample. Finite success proves the universal claim only with coverage. Passing every test seen so far in an open-ended stream still leaves the claim Open.

    The three-valued evidence discipline is related to runtime verification. Fair search deals with starvation; semidecision and observation explain why lack of evidence does not generally decide the other answer. Changing a control resets the experiment.

    07 / Experiment five

    Same result.
    Different journey.

    Type information can justify an optimization. A correctness proof establishes equivalent observations. A cost argument establishes an improvement. Neither says that the two executions must take the same internal steps.

    Equality and cost are separate claimsA mathematical example
    n = 18

    Accumulate from zero

    0 + 1 + 2 + ⋯ + n
    observable result

    Use the closed form

    n × (n + 1) ÷ 2
    observable result
    3 arithmetic operations

    Cost model: each addition, multiplication, and division costs one unit. Loop control is omitted, arithmetic is exact, and there is no constant folding. These are mathematical operation counts, not measured disp timings. Bit complexity and machine overflow require different contracts.

    Why the equality holds beyond the slider

    For n = 0, both sides are zero. If the first n integers sum to n(n + 1)/2, adding n + 1 gives (n + 1)(n + 2)/2. Induction proves the formula for every natural n.

    The proof certifies the result, while the separate operation counts compare these particular evaluation strategies. Trying thirty-one slider positions would not prove the general identity.

    Verified compilation commonly uses simulations that allow different internal steps. Equality saturation stores known equal expressions and extracts according to a cost model. Proof-carrying code separates expensive proof construction from checking a supplied certificate.

    08 / What survives the unification

    There is no single
    “more typed” direction.

    The objects and the order determine the lattice. A relation can identify more values, an analysis can distinguish fewer behaviors, and an implementation can use fewer steps. These are different comparisons.

    What is orderedWhat “up” meansThe structure you get
    Predicates on UAdmit more membersPowerset Boolean lattice, classically. Smaller sets are stronger predicates.
    PERs on UAdd related pairsComplete, generally nondistributive lattice. Membership and equality both move.
    Partitions of a fixed SIdentify more membersPartition lattice. The carrier stays fixed.
    Abstract domains over CLose precisionComplete lattice of upper closures, ordered pointwise.
    Predicates in contextsEntailment in each contextIndexed logical orders; quantifiers connect contexts.
    Proof-bearing typesNo single scalar orderCategories, possibly higher categories. Maps and proof identities matter.
    Checker answersAcquire decisive evidenceOpen below Proved and Refuted. A poset, not a lattice as given.
    ImplementationsA chosen cost comparisonUsually a preorder or a Pareto order. No general lattice guarantee.

    One encoding is not one semantics.

    Trees can encode heaps, traces, proofs, and distributions. Ownership still needs state and resources; probability needs weights; hyperproperties compare multiple runs. A returned-value relation alone forgets those distinctions.

    Arrow types hit a computability boundary.

    Totality over naturals has the shape ∀x ∃t: execution returns a valid answer within t steps. General membership is Π⁰₂, beyond positive semidecision. Resuming every task does not make every semantic function type enumerable.

    Infinite does not always mean unsearchable.

    Some compact higher-type spaces support exhaustive checking under totality and continuity assumptions. That is a property of the represented space and predicate—not permission to declare an unfinished enumeration complete.

    Proofs carry more than a Boolean.

    Dependent families need coherent substitution and transport. Higher identity types retain paths between proofs. Truncation deliberately forgets that structure; an ordinary equality checker does not reconstruct it.

    A normalizer needs a contract.

    Idempotence gives a retraction. A quotient must also respect the base equality and choose valid representatives. A left order adjoint additionally needs monotonicity and an extensive closure property in the chosen order.

    A certificate needs a validator.

    A finite list does not certify its own coverage. A proof search strategy does not establish its own soundness. Even a finite set of transition schemas needs a theorem covering every permitted instantiation.

    Types can be reusable knowledge that makes general computation cheaper. Adjunctions explain some of the ways that knowledge is organized—not every way it is used.
