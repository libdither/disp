# aufbau: how the "Semantic Prefix Oracles" paper's own code does partial parsing and semantic pruning

Scope: the open-source engine behind arXiv 2609.35425 (Paul Kronlund-Drouault, "Semantic Prefix Oracles for LLM Decoding: Contracts and Differential Validation", LMPL '26). Read from a fresh clone at commit `23f856c114adea05c6dd882efa1bd68a7f3e6747` (2026-09-25, the HEAD of `main` as of 2026-10-09). Nothing in the clone was built or run; everything below is from reading files. Every GitHub link is a permalink to that commit; every paper link is a page fragment into the arXiv PDF.

Glossary (the repo's own names, glossed): **aufbau** = the Rust oracle/engine; **p7** = the Python decoding controller that sits on top (not in this repo); **SPG** = the grammar object (productions + typing rules); **Earley** = a chart parser that keeps every surviving reading of a prefix at once; **`.auf`** = the grammar file format; **verdict** = the three-valued answer `Satisfied` / `Live` / `Lost` (API spelling `typed` / `live` / `dead`).

## 2. Partial parsing: the Earley chart, Live vs Lost, ambiguity, incremental reuse, cost

### Takeaway
Each call to `parse()` rebuilds an agenda-driven Earley chart from scratch over a whitespace/keyword tokenization of the whole prefix; a prefix is "dead" iff no item for the start symbol spans the whole input after a final "frontier lifting" pass promotes end-of-input items to `Prefix`/`Extensible` nodes. Ambiguity is kept as multiple packed alternatives per node and multiple roots; typed verdicts are per item and a Lost item is simply dropped, so a prefix is dead only when every reading dies. There is no incremental reuse between consecutive prefixes: `feed`/`mask` fork the parser and re-parse the extended string.

### Cited Findings
- **Item shape.** An `Item` carries `prod`, `dot`, `start`, `pos`, two context ids (`ctx` = "the context this item was predicted at — immutable, and the node's resumption identity"; `mctx` = "Mutable working context: `ctx` with all left-sibling effects applied"), an `Obligations` store, `children`, and `demand: Option<Type>` ("What this occurrence is *for*: the type its parent's premise ascribes to it, canonicalized") — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L44-L72).
- **Chart tables and dedup key.** `Tables` holds an `agenda: VecDeque<Task>`, `seen_process: HashSet<(ProdId, dot, start, pos, CtxId, Option<Type>)>`, `results`/`completed_nodes` keyed by `(nt, start[, end], ctx)`, `waiters` keyed by `(nt, start)`, and a `frontier: Vec<Item>` — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L97-L108). `enqueue_process` dedups on `(prod, dot, start, pos, mctx, demand)` — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L128-L140). The demand is renamed to positional hole names before keying, because "Every evaluation of a rule mints its holes fresh, so the same demand reached twice is two unequal terms. Left alone that makes the process key miss every time and the chart grows without bound" — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L18-L40).
- **An explicitly unproven assumption** sits in the parser: "Any two obligation stores, compatible with the same process key are future-equivalent for the parser. --- Obligation Reconstructibility Hypothesis ---" — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L119-L123).
- **Prediction.** `seed` enqueues one dot-0 item per alternative, but skips any production whose conclusion pattern cannot meet the inherited `demand` ("A production whose conclusion cannot meet `demand` is not predicted at all") — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L146-L186). Alternatives are also pre-filtered by the parent's binding obligations (`Obligations::prune` returns only the alternatives some pending binding path can still reach) — [obligation.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/semantics/obligation.rs#L257-L284), [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L543-L552).
- **Scanning a regex terminal.** `consume` matches the terminal's regex against one whole tokenizer segment and branches on `PrefixStatus`: past end of input → item goes to `frontier`; `NoMatch` → dropped; `Prefix` mid-input → dropped, at end-of-input → a lexeme with `complete=false, open=true` pushed to the frontier; `Complete` → advance; `Extensible` → advance, `open` iff at end of input — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L188-L287). The regex engine is a hand-written one "with Brzozowski derivatives" exposing `PrefixStatus::{Extensible(Regex), Complete, Prefix(Regex), NoMatch}` — [regex/mod.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/regex/mod.rs#L1-L40). A mid-input partial match is dead by test: "mid-input prefix of a terminal should be dead, not a frontier candidate" — [status.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/tests/status.rs#L123-L131).
- **Node status (the paper's Exact/Prefix/Extensible).** `NodeStatus::{Exact, Prefix, Extensible}` with doc "Exact: exact on the current input; node may export context transforms. Extensible: fully recognized but some descendant is still extendable at the right frontier. Prefix: only prefix-accepted; some required descendant is syntactically incomplete at EOF" — [arena.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/arena.rs#L92-L110). `finish` computes it as `(all children complete, any child open) → Extensible`, `(true, false) → Exact`, else `Prefix` — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L289-L295). Right-bound effects are exported only from `Exact` nodes — [elaborate.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/elaborate.rs#L67-L82); the paper's wording is "Only an Exact node exports a declaration into the context its right siblings see" — [arXiv p.3](https://arxiv.org/pdf/2609.35425#page=3).
- **Where a reading dies.** `finish` calls `typing.finalize`; on `Err` (a `Lost` verdict) it logs "finalize rejected" and returns `Ok(None)`, so the item never becomes a node and never wakes a waiter — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L309-L361). The runtime maps `Verdict::Lost` to `Err(TransitionError::Rejected)` — [runtime.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/semantics/runtime.rs#L246-L281). The paper: "A stable contradiction removes that item immediately, while unresolved frontier evidence remains in the chart" — [arXiv p.3](https://arxiv.org/pdf/2609.35425#page=3).
- **Completion and context-sensitivity.** A completed node wakes only waiters whose `child_ctx` equals the completion's `ctx` ("a node predicted at `ctx` must complete at `ctx` or its parent's waiter never fires") — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L398-L448); `resume` applies the child's exported effect to the parent's `mctx` only — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L365-L396). When a child descent cannot yet be resolved (a setting depends on a sibling not yet seen) the parser treats it as "a soft no-op: the parser will re-try once more input arrives" — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L486-L500).
- **Frontier lifting (how "Live" is computed).** After the agenda drains, `lift_frontier` runs "a SEPARATE algorithm from the main Earley loop: No `process()`, no `seed()`, no `consume()`. Just `finish()` items and resume waiters", deduping items on `(prod, dot, start, pos, mctx)` and output nodes on `(nt, span, evidence)` so type-distinct partial readings both propagate while cycles terminate — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L558-L673), [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L779-L793). The verdict: roots are `completed_nodes[(start, 0, end, ctx)]`; if empty the parse returns `Err("no parse found")` (= dead), otherwise the roots are materialized; "typed" means some root `is_complete()` — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L795-L806), [ffi/python/typing.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/ffi/python/typing.rs#L251-L259).
- **Ambiguity representation.** The arena is "a finite directed hypergraph" whose hyperedges (`PackedAlt { prod, children }`) attach alternative derivations to a node; a parse forest is "a rooted sub-hypergraph selected by a root set" — [arena.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/arena.rs#L1-L10), [arena.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/arena.rs#L150-L154). Each node stores its own interned `evidence` (type), optional `effect`, a `binding_map`, and `semantic_complete` — [arena.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/arena.rs#L173-L198). `verify()` reports *every* distinct complete-root type, because `root_type()` "returns whichever complete root comes first and cannot show a conflict" — [synth/verification.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/synth/verification.rs#L1-L13). Paper: "Ambiguity is existential: a prefix is Lost only when every compatible branch is Lost" — [arXiv p.3](https://arxiv.org/pdf/2609.35425#page=3).
- **No cross-prefix reuse.** `parse()` begins with `self.arena = ParseArena::new(); self.tables = Tables::default();` — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L749-L755). `feed` concatenates the token onto the input string, forks the parser (`arena.snapshot()` + cloned tables) and parses the whole extended string; it commits only on success ("Transactional") — [synth/mod.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/synth/mod.rs#L129-L152), [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L685-L695). The only reuse across prefixes is at the runtime level: every rule is compiled to its IR once in `TypingRuntime::new` "so the parser's hot path looks up a `Program` instead of recompiling per node" — [runtime.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/semantics/runtime.rs#L60-L74), and the prefix harness notes "One synth, reused across every prefix: the runtime ... is built once, then `set_input` re-parses" — [parseable/mod.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/validation/parseable/mod.rs#L143-L157). Architecture doc: "Caching is explicit ... No transparent memoization anywhere below the API" — [docs/architecture.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/docs/architecture.md#L148-L156).
- **Measured cost (whole-prefix parse, not per-token increment).** Committed Criterion numbers: STLC application chain with 7 tokens: median 1,152 µs (43 arena nodes); `imp` declaration block with 44 tokens: median 1,987 µs (83 nodes); flat arithmetic sum with 15 tokens: 460 µs; 13-token nested parens: 348 µs — [data/chart_growth.csv](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/data/chart_growth.csv), generated by [benches/chart_growth.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/benches/chart_growth.rs#L66-L138). The paper's own figure: "Median whole-input try_feed time on four synthetic stress families grows smoothly and mildly superlinearly with expression size, at log–log slopes of roughly 1.1–1.4", largest inputs (450-token C declaration sequences) "stay under ∼130 ms", "CPU-only, on a six-core laptop CPU" — [arXiv p.7](https://arxiv.org/pdf/2609.35425#page=7). A separate `engine_perf` binary times grammar load, parse/typecheck, mask/feed, context growth and completeness on STLC with input `"f x0"`, a 32-entry context and the five mask candidates `["λ", "(", "x", " ", "->"]` — [engine_perf.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/bin/engine_perf.rs#L14-L21).
- **Decidability claim.** Proposition 2.2: "evaluation of any finite prefix and masking over any finite candidate set are decidable" — [arXiv p.3](https://arxiv.org/pdf/2609.35425#page=3); the paper gives no polynomial bound.

### Inferences
- "Incremental" in this engine is an API property (`feed` extends a string and keeps the committed state) rather than chart reuse: each step re-parses the full prefix, so over a generation of n tokens the total oracle work is Θ(n × cost(prefix)), i.e. at least quadratic even where the per-parse cost is linear. The benches confirm per-parse cost already grows super-linearly in prefix length.
- The "dead" verdict is computed structurally the same way the chumsky read-probe computes it (no item survives to the end of input), but with two differences: (a) Earley keeps all readings, so a surviving ambiguous reading keeps the prefix alive where a PEG commits; (b) typed `Lost` items are pruned *inside* the chart, so semantic failure can kill a prefix before syntax does.
- The `(mctx, demand)` components of the dedup key mean chart size scales with the number of distinct contexts and demands reaching a span, which is why canonicalizing demands mattered to termination; the unproven "Obligation Reconstructibility Hypothesis" is the soundness debt behind that dedup.

### Gaps
- No per-token or per-mask-candidate timing is committed to the repo; `engine_perf` output JSON is not checked in. The paper's Fig. 3 caption numbers (125 ms at 450 C tokens, 131 ms at 65 STLC applications) could not be matched in the PDF text by the verifier (only the body-text "stay under ∼130 ms" could), so they are listed under Unverified below.

## 3. Semantic layer: rules → IR → executor, unification, evidence/binding statuses, where "stable contradiction" is decided

### Takeaway
A rule is compiled once to a flat instruction list (`Eval`, `Ascribe`, `Equate`, `Member`, `Fresh`, `PushScope`/`PopScope`, `Extend`, `Emit`, `Effect`) with per-binding "splices"; the executor folds it with first-order unification (occurs check on) over type trees and three-valued premise statuses. `Lost` is produced only by a `Contradiction`, and a unification failure counts as a contradiction only when `failure_is_stable` holds (always in the rewrite-free theory; only on ground terms when rewrites exist) *and* the child's lexeme is not still open at the right edge — the two conditions that make the refutation survive any extension.

### Cited Findings
- **Pipeline and the "cut".** `ls src/` is the pipeline: `regex/` → `grammar/` → `parse/` → `ast/` → `typing/` → `synth/`; the one internal cut is `typing::ir::compile`: "grammar (.auf) --parse--> TypingRule --compile--> Program --run/descend--> Verdict"; "The executor satisfies, leaves `Unknown`, or prunes. It never extends." — [docs/architecture.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/docs/architecture.md#L1-L26), [docs/architecture.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/docs/architecture.md#L48-L85). "The one runtime-side safety mechanism is the three-valued prune, and it only ever rejects; it cannot admit." — [docs/architecture.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/docs/architecture.md#L159-L166).
- **Attaching rules to productions.** `Name(rule) ::= ...` binds a rule name to a nonterminal; `Child[b]` binds a subtree to a name usable in that rule; `Type*` marks the type fragment so type expressions in rules are parsed by the grammar itself ("There is no built-in arrow, product, or union: `?A -> ?B` means whatever the type fragment's productions make of the text") — [GRAMMAR.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/GRAMMAR.md#L43-L97), [GRAMMAR.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/GRAMMAR.md#L141-L146). Loading rejects "a rule pattern with no unique parse at the type sort, rather than silently weakening it to `⊤`" — [GRAMMAR.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/GRAMMAR.md#L94-L95). The STLC rules are `x ∈ Γ ⟹ Γ(x)` (var), `Γ[a:τ] ⊢ e : ?B ⟹ τ -> ?B` (lambda), `Γ ⊢ l : ?A -> ?B, Γ ⊢ r : ?A ⟹ ?B` (app) — [stlc.auf](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/python/aufbau/examples/stlc.auf#L29-L40).
- **The IR (the paper's "term evaluation, ascription, equality, context membership, scoped extension, and right-bound effects", [arXiv p.2](https://arxiv.org/pdf/2609.35425#page=2)).** `enum Instr { Eval{dst,expr}, Ascribe{binding,expected}, Equate{left,right}, Member{key}, Fresh{key}, PushScope, PopScope, Extend{key,ty}, Emit{ty}, Effect{key,ty} }` — [ir.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/ir.rs#L32-L57). A `Program` is `name + instrs + splices: HashMap<binding, Range>`; a splice is "the settings span" of the premise that ascribes a binding — the `Extend`s to apply when descending into that child — and deliberately excludes the `Ascribe` itself, which "is the rule's check, applied during `finalize`" — [ir.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/ir.rs#L59-L83), [ir.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/ir.rs#L150-L164).
- **Compilation.** `compile` walks premises then the conclusion: a premise with context extensions is bracketed `PushScope`…`PopScope`; each extension becomes `Eval` + `Extend`; an ascription becomes `Eval` + `Ascribe` and records `splices[binding] = setting_start..ascribe_eval_start`; a membership/freshness records a splice only when keyed by a binding; an equation becomes two `Eval`s and an `Equate`; the conclusion emits each `Effect` then one final `Emit` — [ir.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/ir.rs#L86-L205). A static pass `typing::check` runs at grammar load and "rejects programs that are malformed as schedules: unbalanced scopes, a register read before it is written, overlapping splices, a missing or non-final `emit`, and any binding an instruction names that no production declares", because at runtime "an unresolvable name is reported as 'not known yet'" and would stay `live` forever — [docs/architecture.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/docs/architecture.md#L111-L121).
- **Types are first-order trees; unification is Robinson/Martelli–Montanari with an occurs check.** `Term::{Var(String), Con(String, Vec<Term>), Leaf(Pattern)}` where a leaf is "a base type as a regular set"; `Evidence { term, eqs }` carries "residual equations" on metavariables visible outside the node — [term.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/term.rs#L19-L50). `unify`: ⊤ "unifies with everything and binds nothing" (a top rule, not a variable); `(Var x, t)` binds unless `occurs_check && occurs(x,t)`; `Con` requires same label and arity; two leaves unify iff their regular sets intersect; `Con` vs `Leaf` clashes — [term.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/term.rs#L249-L292). With `occurs_check=false` "that binding stands and `s` denotes a rational tree — a recursive type" — [term.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/term.rs#L260-L263); every call site in the executor passes `true`.
- **Metavariables are global across the tree.** "a rule's holes are α-renamed per evaluation (`?A` → `A#run`), and the bindings an evaluation discovers on *foreign* variables (a child's, a sibling's) are exported as the residual equations of its `Evidence`. Parents merge children's equations before running their own rule" — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L1-L11); `merge_eqs` unifies each child equation into the substitution and returns `Contradiction` only on a *stable* conflict — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L299-L328); `export` collects bindings on non-local variables — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L330-L341). Polymorphism exists only as `inst(x)`, which freshens a context entry's variables at a use site — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L34-L41), [GRAMMAR.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/GRAMMAR.md#L141-L174).
- **Context.** Two separate maps, `bindings` (keyed by input text) and `ambient` (keyed by grammar-fixed names like `'return'`), because sharing one namespace "makes C's `return;` type-check as an expression statement reading a variable called `return`" — [context.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/context.rs#L18-L31), [docs/architecture.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/docs/architecture.md#L87-L109). `lookup_starts_with` serves open identifier prefixes — [context.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/context.rs#L52-L57).
- **Evidence statuses and Pending/Resolved bindings.** A consumed terminal is a `Lexeme { matched, open, complete }`: "`complete` — the regex is fully satisfied, so the Earley item advances. `open` — at end-of-input the lexeme could still grow" — [arena.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/arena.rs#L137-L148). `BindingStatus::{Resolved{span, complete, open, evidence}, Pending{position}}` "materializing β(ν,b) (Def. 5)" — [arena.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/arena.rs#L156-L171); an `Obligation` (one per binding the rule uses, with grammar paths to where the binding can be filled) becomes that status at `finish` — [obligation.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/semantics/obligation.rs#L12-L36), [obligation.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/semantics/obligation.rs#L129-L164). Paper: "A binding moves from Pending to Resolved, never the reverse" — [arXiv p.3](https://arxiv.org/pdf/2609.35425#page=3). Premise statuses form the lattice "Contradiction < Unknown < Satisfied"; rule results are `Success((Evidence, Option<ContextTransition>))`, `Partial(Evidence)`, `Contradiction` — [rule.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/rule.rs#L42-L74).
- **Where "stable contradiction" is decided (the exact code).** (1) `TypingDomain::ascribe`: on unification failure, `if open || !failure_is_stable(norm, expected, actual) { Unknown } else { Contradiction }`, with the doc: "Holes in either term can be instantiated — and unification failure is preserved under instantiation, so that is not a reason to wait. Or the actual term can be *replaced* wholesale, which is what `provisional` marks; there we must wait" — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L263-L297). (2) `failure_is_stable(norm, a, b) = norm.rules().is_empty() || (a.is_ground() && b.is_ground())`: "In the free theory, yes: the only failures are rigid-rigid clashes and occurs-check violations, and both survive any substitution. With rewrite rules, only if both sides are ground: a hole can block a redex, so instantiating it may enable a rewrite that repairs the clash" — [normalize.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/normalize.rs#L146-L156). (3) `run_ascribe` returns `Unknown` when the binding's obligation has no value yet, `Unknown` when the child's evidence is missing but the lexeme is open and `Contradiction` when it is closed, and `Unknown`/`Contradiction` for a missing obligation depending on whether the node is open (`allow_missing = status.open()`) — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L415-L454), [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L540). (4) `run_member`: a literal key is decided outright; a binding key is `Satisfied` if the text is in Γ or (lexeme open and some key starts with it), `Unknown` if the text is empty, else `Contradiction` — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L456-L489). (5) `run_fresh`: a duplicate name is `Unknown` while the lexeme is still open ("more identifier text may make it fresh"), `Contradiction` once closed — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L491-L523). (6) `Equate` uses the same `failure_is_stable` gate — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L707-L730). (7) In `run`, the `combine!` macro returns `RuleResult::Contradiction` at the first contradiction and downgrades `satisfied` on any `Unknown`; a run with no emitted type or any `Unknown` is `Partial` — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L549-L558), [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L739-L759). (8) `finalize` maps `Contradiction → Lost`; `Partial → Live` if the node status is open, else `Lost`; `Success → Satisfied`, exporting the effect only when `status == Exact` — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L966-L1021). The paper's list: "This includes rigid constructor clashes, regular-leaf clashes, occurs-check failures, and failed l[ookups]" — [arXiv p.3](https://arxiv.org/pdf/2609.35425#page=3).
- **Why this avoids false prunes (the design argument in the code).** The refutation is gated on two monotone facts: (a) in the free theory a rigid clash or occurs failure cannot be undone by instantiating holes; (b) a node that is still `open`/`Prefix` may be *replaced* by a longer node filling the same obligation at a different type, so refuting against it is unsound — the regression list spells this out: "at `(h +` the arm body is a parenthesised `int`, and the obligation ends up filled by `(h + 1) :: t` at `int list`" — [verdicts.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/validation/parseable/verdicts.rs#L23-L43). The changelog records the switch from "gating on the child's mere openness" to stability: "`let x : Bool = 1` is now dead at the `1`" — [CHANGELOG.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/CHANGELOG.md#L23-L27).
- **Prediction-time refutation (`descend`/`admits`).** `descend` replays the instructions before a binding's splice to recover the substitution earlier premises fixed, applies the splice's `Extend`s to build the child context (also enforcing `Fresh`), then reads the child's *demand* from the `Ascribe` immediately after the splice, "under (F) it is fixed before the occurrence is entered -- which is what makes it usable at prediction" — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L766-L913). `conclusion_pattern` builds the rule's conclusion with every input-dependent part (`Ref`, `Ctx`, `Inst`) replaced by a *distinct* fresh hole — "forcing two unresolved positions equal would be a stronger claim than the rule makes" — and `admits(program, demand) = unify(pattern, demand) || !failure_is_stable(pattern, demand)` — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L987-L1036). Changelog: "a production whose conclusion pattern cannot meet it is refused at prediction rather than after it consumes input" — [CHANGELOG.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/CHANGELOG.md#L11-L17). A rule-less production passes the demand through unchanged — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L532-L541).
- **Rule-less nodes.** A node with no rule gets *structural* evidence: its own parse tree as a `Con` over child evidence (or a `Leaf` of its text) — this is how a written type annotation becomes a term rules can unify with — [elaborate.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/elaborate.rs#L1-L55), [runtime.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/semantics/runtime.rs#L121-L151). A rule-less single-nonterminal wrapper is "transparent" and inherits its child's evidence — [grammar/mod.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/grammar/mod.rs#L154-L183).

### Inferences
- The soundness of `Lost` rests on three monotonicity facts of first-order terms: substitution preserves rigid clashes, Γ only grows under `∈`, and a closed lexeme cannot change. The one anti-monotone premise, freshness `∉`, is handled by refusing to refute while the identifier is still open — PLAN.md records the worry ("`∉` (freshness) is anti-monotone: extending the context *can* falsify a premise that held") and the reviewer's resolution that `dead` stays sound "iff the freshness binder ranges over an infinite language" — [PLAN.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/PLAN.md#L58-L66), [PLAN.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/PLAN.md#L76-L86).
- Adding a rewrite theory *weakens* pruning: with any rewrite rule present, a clash between two non-ground terms is `Unknown`, so the engine refutes only ground mismatches. The code acknowledges that unification modulo a theory with variables on both sides "needs narrowing (= search)", left as a future "kanren layer" — [normalize.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/normalize.rs#L18-L24).
- `Partial` on a syntactically *closed* node is `Lost`: an obligation that never resolved by the time the production is complete kills the reading. That is where `typing::check`'s load-time check of undeclared bindings matters — without it such a rule would never type anything and the failure would be silent.

### Gaps
- The correspondence between the code's `PremiseStatus`/`RuleResult`/`Verdict` and the paper's Definition 2.3 is by naming only; the Rocq development treats `eval_rule` as an opaque parameter and lists "`eval_rule`'s ascription step agrees with `unify_modulo`" and "`Lost` is not merely 'unproven' but unreachable" as unproven obligations — [verification/domain.v](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/verification/domain.v#L37-L73).

## 4. Tokenizer lifting: how LLM vocabulary tokens meet a character-level grammar

### Takeaway
There is no vocabulary trie, DFA, or precomputed mask: `mask(candidates)` just tries each candidate string by appending it to the prefix and re-parsing on a fork. Partial tokens are handled by re-tokenizing the whole concatenated text (so a boundary inside an identifier or inside a multi-character literal like `->` becomes an "open" lexeme or a "partial special" segment) and by regex derivatives giving `Prefix`/`Extensible` status. The decode loop above the engine (p7) is rejection sampling with a retry budget; a vocabulary-wide mask is an open work item.

### Cited Findings
- `Synthesizer::mask(&[String]) -> Vec<bool>` is `candidates.iter().map(|t| self.try_feed(t).is_ok())`, and `try_feed` does `format!("{}{}", self.input, token)`, forks the parser, and parses the whole extended string — [synth/mod.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/synth/mod.rs#L154-L173). The Python binding is the same loop, documented as "One Rust-side pass over the whole candidate set, no state change" — [ffi/python/typing.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/ffi/python/typing.rs#L208-L216); README: "`mask(candidates)` — the constrained-generation primitive: one bool per candidate continuation, no state change" — [README.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/README.md#L65-L66).
- Candidate spelling is taken literally, leading whitespace included: `Synthesizer("start ::= 'a' 'b'", "a").mask([" b", " a", " c"]) == [True, False, False]`; on STLC after `λx:A.` the mask of `["x", "(", "#"]` is `[True, True, False]`; and a test asserts `mask` agrees with `feed` candidate by candidate — [test.py](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/ffi/python/test.py#L345-L355), [test.py](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/ffi/python/test.py#L610-L623), [feed.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/synth/tests/feed.rs#L143-L152).
- The engine's own tokenizer: every quoted literal in the grammar is registered as a "special token" at load — [load.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/grammar/load.rs#L74-L76); `tokenize` splits on whitespace delimiters, matches specials longest-first with a word-boundary rule for word-like keywords (`in` inside `inc` is not a keyword), and a trailing fragment that is a proper prefix of a special (e.g. `-` of `->`) becomes an `is_partial_special` segment — [tokenizer.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/grammar/tokenizer.rs#L208-L234), [tokenizer.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/grammar/tokenizer.rs#L236-L271); a character-class transition rule prevents `Int` being split as `In` + `t` just because `t` prefixes `then`/`true` — [tokenizer.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/grammar/tokenizer.rs#L305-L317).
- A segment that only partially matches a regex terminal at end of input becomes an open lexeme (`complete=false, open=true`) that keeps the item on the frontier; `Extensible` (a full match that could still grow, e.g. an identifier) is `complete=true, open=at_end` — [parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L233-L254). Open lexemes flow into typing: `x ∈ Γ` is `Satisfied` on an open identifier prefix if any context key starts with it — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L478-L488); the regression list has `let x : Bool = tru` live because "tru extends to the keyword true" and `let x : Int = tru` dead because "tru extends only to the keyword true, and the context is empty" — [verdicts.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/validation/parseable/verdicts.rs#L44-L56), [verdicts.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/validation/parseable/verdicts.rs#L95-L123).
- Paper (Lemma 3.1 and §3.1): "Under exact spelling (the oracle consumes, byte-for-byte, the text the model conditions on)", "the exact spelling map on ordinary text tokens of the vocabulary", "regular derivatives carry the oracle's state across a token ending inside a terminal recognizer", "Character-level witness existence therefore lifts to token-sequence reachability" — [arXiv p.5](https://arxiv.org/pdf/2609.35425#page=5); Figure 2: "Lost is excluded and resampled" — [arXiv p.5](https://arxiv.org/pdf/2609.35425#page=5).
- The decode loop and its cost, from the plan: "Today's decode loop is rejection sampling: sample a token, screen 2–3 spellings via `Synthesizer.mask`, exclude and resample, bounded by `max_retries` (2048)"; "cost is O(retries) FFI round-trips per emitted token; it cannot become a vLLM logits processor, which wants one vectorized mask over the whole vocabulary per step"; open item: "Build a cached vocabulary-wide mask: a trie or DFA over the tokenizer vocabulary, keyed by synthesizer state" — [PLAN.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/PLAN.md#L184-L204).
- `in_scope(expected)` returns the context names whose type unifies with a given type — "the type-filtered set of identifiers a generator may emit at a hole" — [ffi/python/typing.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/ffi/python/typing.rs#L218-L249).

### Inferences
- Per decoding step, the oracle cost is (number of candidates screened) × (full re-tokenize + re-parse of prefix+candidate). With 2–3 spellings screened per sample and retries on Lost, this is a handful of full parses per emitted token; the benches put a full parse of a ~40-token prefix at ~2 ms, so tens of ms per emitted token is plausible at that size, growing with prefix length. No code measures this directly.
- Because the whole text is re-tokenized every time, there is no "token boundary state" to carry; the price is that the engine cannot exploit the previous step's chart. This is the opposite trade-off from a derivative/automaton approach that carries state and never re-reads.

### Gaps
- The retry-pressure percentages and the exact sampling loop live in p7, which is not in this repo; the paper's per-model retry rates (reported in its §4.3) are listed under Unverified because the verifier could not match them in the PDF text.

## 5. Dead-end freedom: (P), (T), (F) in code, and the STLC counterexample

### Takeaway
No code checks the paper's three conditions. The nearest thing is `typing::complete::completeness()`, a sufficient-only certificate that classifies a grammar as `syntactic`, `inhabited` (every ascribed sort has a *universal* inhabitant — one closed term whose type is a bare hole — and every freshness binder is infinite) or `sound` with named blockers. (F) is assumed by the architecture rather than tested. On the STLC counterexample the engine keeps the prefix Live; the repo records this and an analogous `fun` dead end as "the honest record of the oracle's imprecision".

### Cited Findings
- Paper Definition 2.5: (P) "Every reachable nonterminal has a finite completion, and every reachable regular residual is nonempty"; (T) "Every reachable type demand has a finite closed realizer"; (F) a child's obligations are "determined by the parent demand, the fixed context, and children to its left"; Theorem 2.6: a grammar satisfying them "is dead-end free: every Live prefix has a witness" — [arXiv p.4](https://arxiv.org/pdf/2609.35425#page=4). Counterexample: with A, B distinct atoms, `λf:A→B. f(` demands a term of type A; "If the language has no closed term of type A, the prefix is Live but has no witness" — [arXiv p.4](https://arxiv.org/pdf/2609.35425#page=4).
- The certificate: "Safe pruning is unconditional: `dead` means no continuation exists. The converse ... is *semantic inhabitedness* (`def:inhabited`), PSPACE-complete in general. This module decides a sound, conservative certificate"; classes `Syntactic`, `Inhabited`, `Sound { blockers }`; "The certificate is sufficient, not necessary" — [complete.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/complete.rs#L1-L59). `completeness(g)`: no rules → `Syntactic`; else compute `infinite_sorts`, `universal_sorts`, and report every ascribed sort not universal (plus `"freshness"` if any freshness binder is finite) as blockers — [complete.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/complete.rs#L81-L105). `universal_via` requires the conclusion to be a bare hole or ⊤ with no effects, every premise an ascription of a child that is itself universal (or freshness over an infinite binder) — "Membership and equation premises never certify" — and all other children productive — [complete.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/complete.rs#L158-L199). `productive_sorts` is "standard CFG productivity, ignoring types" — [complete.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/complete.rs#L107-L117); `infinite_sorts` is a fixpoint over `regex_is_infinite` — [complete.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/complete.rs#L201-L241).
- Tests pin the classification: `stlc_is_sound_only` ("The draft's counterexample: `λf:A→B. f(` is live but uninhabited"), `ml_is_inhabited` ("`assert false : ?A` is the universal inhabitant"), and `ml_without_diverge_is_sound_only` (pinning `diverge` to `'int'` drops the certificate) — [complete.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/complete.rs#L353-L383). GRAMMAR.md: "`sound` grammars may still be complete in fact (STLC's `λf:A→B. f(` is the canonical live-but-uninhabited prefix; adding a diverging term moves the grammar into `inhabited`)" — [GRAMMAR.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/GRAMMAR.md#L193-L216). ML's `Diverge(diverge) ::= 'assert' 'false'` with conclusion `?A` is in the grammar for exactly this reason — [ml.auf](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/python/aufbau/examples/ml.auf#L48-L51), [ml.auf](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/python/aufbau/examples/ml.auf#L140-L142); paper: `assert false` "is a universal expression inhabitant" — [arXiv p.5](https://arxiv.org/pdf/2609.35425#page=5).
- `fun.auf` documents the other route to (T): "not with a single term that inhabits every type ... but with a *distributed* cover — one witness per demanded type", which "only works if the set of demandable types is exactly the set of covered ones, which is why TypeName is a closed enumeration" (`'Int' | 'Float' | 'Bool'`) — [fun.auf](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/python/aufbau/examples/fun.auf#L1-L26).
- (F) in code: `descend` reads the child's demand from the premise after its splice "under (F)" — [domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L892-L897); nothing verifies that a grammar's rules actually satisfy it.
- Behaviour on an uninhabited demand: the `KNOWN_DEAD_END` list records `fun`'s `let n : Int = 1 ; let x : Bool = n` as "Accepted today with **no** completion at all: the honest record of the oracle's imprecision, and the gap between the shipped evaluator and the one the dead-end-freedom theorem describes", because `var` concludes `Γ(x)` whose prediction pattern "is a bare hole — so it admits everything" — [verdicts.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/validation/parseable/verdicts.rs#L125-L143). The OCaml report prints "certified (inhabited)" or "sound (uninhabited sorts)" per language — [certify.ml](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/ocaml/certify.ml#L28-L42).
- The formal side: `gen_sound` and `gen_complete` ("Theorems 4.6 / 4.7 of the draft") are `Admitted`, because their proofs "depend on a per-domain `step_sound` obligation ... which does not exist yet for the real typing domain" — [OBLIGATIONS.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/verification/OBLIGATIONS.md#L12-L22); the generator is a functor over an abstract `GenDomain` — [generation.v](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/verification/generation.v#L21-L29); the whole development is 466 lines across six `.v` files (counted on the clone).

### Inferences
- The code's certificate is strictly stronger than the paper's (T): it demands a *single* universal inhabitant per sort, while (T) only needs a realizer per reachable demand. By the code's rules `fun.auf`'s literal rules conclude constants (`'Int'`, `'Bool'`), not a bare hole, so `universal_via` would not certify `Expression`; I therefore expect `completeness(fun)` to return `sound` even though the grammar header (and the paper) argue it is dead-end free by distributed cover. I did not run the code, so this is a reading, not a measurement.
- Nothing stops a grammar author from writing rules that violate (F) (e.g. a right sibling constraining a left one); the engine would still be sound (it would just leave things `Unknown` longer), but Theorem 2.6's completeness guarantee would silently not apply.

### Gaps
- No test or tool exercises the STLC counterexample end to end (feeding `λf:A->B. f(` and asserting Live-with-no-witness); the only pins are the completeness classification and the `fun` dead-end entry.

## 6. Differential validation harness against ocamlc and cc

### Takeaway
Two harnesses read the same `corpora/<lang>/{valid,invalid,beyond}.txt` files: a Rust test module checks the engine's verdicts directly, and an OCaml program (`ocaml/cert.ml`) checks them against OCaml's own typechecker (via compiler-libs) and against `cc -fsyntax-only -Wall -Werror`, exiting non-zero on any disagreement. Prefix-level checks (every token-boundary prefix of a valid program must stay accepted) live in the Rust `parseable` suites and the CLI `aufbau validate`; the committed corpora are smaller than the paper's cohort.

## 7. Limits noted in code, docs, or plan

### Takeaway
Documented limits: no self-recursion at the top level of C or ML (dropped as unsound), monomorphic typing with `inst(x)` as the only generalisation, higher-order recursive list functions do not type, one recorded prefix-completeness gap, grammar-load performance cliffs in the C grammar, weaker pruning under rewrite theories, and a stale open issue in a search component.

### Cited Findings
- Self-recursion dropped: "a self-recursive call's own argument types can resolve that metavariable before the real parameter list does, letting a wrong-arity or wrong-type self-call through — a genuine unsoundness, not a grammar limitation" — [c.auf](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/python/aufbau/examples/c.auf#L25-L32); ML's top-level `Define` has no `rec` ("a definition sees the ones before it, not itself. ## 8. What disp could reuse, and what it must do differently

### Takeaway
Reusable: the three-valued verdict with refutation gated on a *stability* predicate; prediction-time filtering by a conclusion skeleton; witness-checked "must stay live / must stay dead" regression lists; a least-fixpoint inhabitation certificate; corpus-driven differential checks against a trusted checker. Not transferable as-is: everything that makes aufbau's `Lost` sound rests on first-order term unification (rigid clashes survive substitution), whereas disp's types are programs deciding membership, so disp needs its own monotone notion of "this partial program can no longer be accepted".

### Inferences
- *Same shape as the chumsky read-probe.* aufbau's syntactic "dead" is exactly "no item survives to the end of input"; its advantage over a PEG probe is only that Earley keeps every alternative, so ordered choice never causes a false "dead". If disp keeps the chumsky probe for syntax, the semantic layer is the part to borrow.
- *What "stable contradiction" would have to mean in disp.* aufbau can prune because a first-order clash is preserved by every substitution. In disp a type is a program answering yes/no on a value; a partial program has no "term" to clash. The analogue is a *monotone* abstraction of the partial program (e.g. a set of possible values, or an abstract value in a lattice where extension only refines) together with the guarantee that if the type-program answers "no" on the whole abstract set, it answers "no" on every refinement. Without such monotonicity there is no sound `Lost` at all — only `Live`.
- *Openness gating transfers directly.* aufbau never refutes against a node that can still be replaced by a longer one at the same position. The equivalent disp rule: never evaluate a type against a subterm whose right edge is still growing; evaluate only against closed subterms plus holes.
- *Prediction-time demand filtering is cheap and sound only because conclusions are syntactic patterns.* In disp a "conclusion" would be a type-program; the only cheap filter is on the *syntactic* category of what can start here (which chumsky already gives). A semantic filter would need the type-program to be runnable on an abstract/partial value.
- *Costs to avoid repeating.* aufbau re-parses the whole prefix per candidate, keys its chart on (context, demand), and has no vocabulary mask; disp's incremental design should carry state across tokens and compute one mask per step, which aufbau's own plan calls "the real performance work in the whole stack".
- *Testing discipline worth copying.* Three lists — must-stay-live (with a checked witness), must-stay-dead, known-dead-ends — plus token-boundary prefix monotonicity over valid programs, plus a differential check of whole programs against a trusted checker. The repo's history shows why the witness matters: without it, stale test data impersonated a soundness bug for weeks.
- *Completeness is grammar-specific, not engine-specific.* Dead-end freedom came from adding a universal inhabitant (`assert false`) or a closed base-type enumeration to the grammar, not from the engine. For disp, "every live prefix has a completion" would similarly be a property of which programs/types the search space admits, and will generally fail (a type with no inhabitant is a legitimate disp type).

### Gaps
- No data here on how aufbau behaves with dependent or value-indexed types; its type language is first-order terms over a sub-grammar, and PLAN.md lists "path-refinement or dependent types carrying the argument value" as unscheduled research — [PLAN.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/PLAN.md#L234-L257).
