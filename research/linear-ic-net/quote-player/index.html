The quote-and-table net

A λ-calculus that can read its own code, run as an interaction net. Code has four kinds of piece: a function \x. b, an application f a, a quote 'M (the code M, handed over as a value without running it), and the atom ρ (a value with no parts). A fifth piece, the table [k1 | k2 | k3 | k4 | k5], reads code: it has one slot for each kind of value (function, application, quote, atom, table).

Applying a table to a value runs the slot for the value's kind, handed the table itself and then the value's parts. So a table is its own loop: a slot reads a part by applying the table it was handed. Applying a quote of a function or a table opens it: the code it would run comes back unrun. That is all the self-interpreter needs (interp, below). This is the candidate of candidate_systems.md, §3.

Click a bright wire, or either agent on it, to fire that pair. ▶ steps in the order chosen under the bar. Drag the bar to scrub through the run, either way. Hold Shift to light up the whole subnet under the pointer.

What you are looking at

Each shape is an agent, each line a wire. Two agents joined by their main ports (a bright wire, in the colour of what the rewrite will do) are about to rewrite; nothing else can happen. The program hangs from the root (the ring at the top), and its answer ends up there.

Code is frozen. Grey shapes are code: functions (λ), applications (small disks), and variables (dots). A thaw (green arrow) walks down code and turns each application into a running application (pink @). It stops at a function: the body stays code until the function is called. When a running application meets a function, the argument goes to the variable's uses and a thaw starts on the body.

A quote is a variable. One agent does both jobs: its lower pin leads either to its function (a variable) or to a piece of code (a quote). A thaw meeting it hands on what is there, unrun. So a variable gives its value, and a quote gives its code as a value. A running application that meets a quote turns into an application that opens (violet): meeting a function, it wires the argument in and hands the body back as code, running nothing.

Tables. A table (teal) has five slot pins, each in its own colour: Applied to a value, it becomes a table reading (cyan), which looks at the value through its left pin. When the value arrives, the slot for its kind is copied: one copy goes back into a rebuilt table, and what is left is code, the other copy applied to the table and then to the value's parts, each quoted. A plain application runs that code; an application that opens hands it back.

Copying happens only where a value is used twice (a split, thin violet Y, sits on the variable's wire), and where a table reads (the slot it takes). Copiers (thick Y, one colour per copy) walk through a value one agent at a time and leave two of each. On a variable's way to its uses a copier faces out, and where it meets the copier facing in of the same copy, the two cancel. Erasing happens only where a variable is not used: an eraser (red ×) walks through the value.

Structures. Code that hangs together sits on one faint band: one value, or one stretch of code. A band's label is the name of the part it comes from, or else the start of its term.

Terms. Point at an agent to read the subnet under it as a term, and see the whole net as one above. In a term, 'M is a quote, and also a variable that has its value M; [a | b | c | d | e] is a table; ▸c is a thaw on code c; f @ a an application that is running, f @' a one that opens; read⟨v⟩ a table reading v; ⧉n⟨v⟩ a side of copy n that has still to pass through v. Where the answer is a boolean or a Church numeral, its meaning follows it (false is also 0).

Named parts. Named code (the table size, interp, …) that nothing is acting on is drawn as its name on a pill. Click a pill to open it, and the tag of an opened part to fold it again. A part opens by itself when something reaches it.

Ports. Every port is a pin on its own side of the icon, and wires join pin tips. The main port's pin ends in a white dot. Only main ports meet: a rewrite happens where two main ports are wired together, and it rewires what was on the side ports. An icon turns, and flips left for right, to face its pins toward what they are wired to; its letter stays upright.

Physical. Tick it and play: the two agents of every pair that can fire are drawn together, and the pair rewrites when its main pins touch. What is close goes first.

Order does not matter. Fire pairs in any order you like, or pick another order under the bar: the answer is the same, and so is the number of rewrites. A pair you fire replaces what was planned from that moment; the rest of the run is planned again, and its length does not change.

Drag an agent to move it; drag empty space to move the view, and scroll to zoom. The shapes named here are the suggested icons; others can be chosen.
