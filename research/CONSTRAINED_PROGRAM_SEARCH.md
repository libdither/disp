# Steering program search with an undecidable, budgeted type checker

> Research note, 2026-10-09. The question: what does the field know about constraint-driven generation and program search (deciding token by token or hole by hole whether a partial program can still be completed into one that satisfies a grammar, scope rules and types, and using that to steer generation); how does it combine with type theories that are modular (the type theory is a swappable parameter or a program), fuzzy (verdicts that are partial, approximate or probabilistic) or compute-parameterized (the verdict depends on a step budget); and how do reinforcement learning from verifier feedback and formal systems unify into one training-and-search loop. Everything is read against disp's exact problem: an optimizer that searches programs with "type checker accepts" times a cost score as the objective, where the type checker is itself a program that may be undecidable or expensive. Method: seven literature sweeps (grammar- and type-constrained decoding; type-directed and enumerative synthesis; gradual, soft and three-valued types; cost-aware and modular type theories; verifier-gated LLM search; RL from verifier feedback; self-play and reward hacking), one implementation read-through (the Earley-based oracle engine behind the September 2026 "Semantic Prefix Oracles" paper, read at a fixed commit without running it) and one experiment (the Rust parser-combinator library chumsky as a prefix oracle). Every source was fetch-verified with scripts/verify-source.sh (the per-sweep notes, with each source's quote, status and minted link, are in research/constrained-program-search/); fragment links (#page=N, #anchor) land on the quoted passage; figures the notes could not re-locate verbatim are omitted or marked unverified. Nothing here is landed or implemented. Delete this file once the optimizer design document (research/OPTIMIZER.typ) carries these citations in its search, trust and build-order sections.

**The answer in one paragraph.** Deciding whether a partial program can still become an accepted one is type inhabitation of a residual constraint, which is PSPACE-complete already for simple types and undecidable for polymorphic and dependent types, so a decoder or synthesizer that wants a per-step verdict has exactly three honest outputs: a refutation that comes with a witness, a proof that exhausts or covers the space, and a budget-bounded "don't know". Every working system since 2021 converged on one contract for the first of these, safe pruning (never reject a prefix that has a completion), proved it by requiring the contradiction to be stable under every extension, and declined to promise the dual, dead-end freedom (every accepted prefix has a completion), because that is a property of the language, not of the oracle. Grammar masks now cost microseconds per token; semantic masks cost tens of percent of decode time on restricted fragments; nobody runs a dependent type checker inside a token-mask loop, and the one measured attempt to constrain with an incomplete oracle lost up to 97% of functional correctness. Masking also samples the wrong distribution: hard masking is a Doob transform with h equal to 1 on every live prefix, whereas the right h is the probability that a random completion is accepted, which is the same quantity a learned value function estimates for search, so the sampling correction and the search heuristic are one object. On the type-theory side that object already has semantics: step-indexed types ("behaves as τ for k steps"), three-valued runtime verification, bounded model checking and SMT's unknown are all monotone in budget, and the gradual-typing fire triangle says the don't-know cannot be eliminated without paying in normalization or conservativity. Cost-aware type theories prove cost bounds about programs and never budget the checker; the only dependently typed checker with a literal step cap and a "gave up" outcome is Cayenne (1998), and the only way to drop fuel from a canonical checker is to postulate strong normalization, which disp cannot do for arbitrary tree-calculus programs. On the learning side, the proof assistant now occupies every slot in the RL loop (reward, filter, curriculum, labeller); process reward models are policy-weighted completability estimates, a lower-biased soft version of the hard oracle; RL with a KL penalty is Bayesian conditioning on the verifier, so training amortizes a search that sampling plus an exact verifier would also win; and every loop that let the generator touch the specification or the trusted base was gamed. For disp the unification is: the hard oracle supplies Refuted and Proved, the budget supplies Open, a learned value supplies the soft order over Open prefixes, sequential Monte Carlo (or a mask for the Refuted half only) applies it at decode time, RL amortizes it into the proposer, and a trust ledger (witnesses replayed by the canonical stream, read-only statements, axiom-style audits, adversarial probes for vacuous types) keeps the loop honest.

## 1. Prefix liveness is type inhabitation, so a third verdict is forced

Take a partial program p, syntactic or hole-shaped, and ask whether some completion of p is accepted by the type checker. If p has a hole whose expected type is T in context Γ, the question is whether T is inhabited under Γ: liveness of a prefix is inhabitation of the residual constraint the prefix leaves behind. That question has known complexity. For the simply typed lambda calculus it is PSPACE-complete (Statman 1979, stated in the Sørensen–Urzyczyn lecture notes as "the inhabitation problem for the finitely-typed lambda calculus is PSPACE-complete" ([Lectures, p.111](https://disi.unitn.it/~bernardi/RSISE11/Papers/curry-howard.pdf#page=111))). For System F it is undecidable, via Löb's embedding of first-order classical logic into second-order intuitionistic propositional logic ([Lectures, p.210](https://disi.unitn.it/~bernardi/RSISE11/Papers/curry-howard.pdf#page=210)), a result Urzyczyn re-proved syntactically for F and Fω in 1997 ([Urzyczyn, TYPES list](https://www.cis.upenn.edu/~bcpierce/types/archives/1996/msg00387.html)). For the dependent calculus λP it is undecidable because λP is conservative over first-order intuitionistic logic, which is undecidable even in its ∀/→ fragment ([Lectures, p.177](https://disi.unitn.it/~bernardi/RSISE11/Papers/curry-howard.pdf#page=177)). Even the finite, monomorphic component-library setting is EXPTIME-complete, k levels of polymorphic instantiation make it (k+2)-EXPTIME-complete, and with arbitrary axiom schemes (an arbitrary polymorphic library) inhabitation is undecidable already in simple types ([Düdder et al., CSL 2012, p.1](https://drops.dagstuhl.de/storage/00lipics/lipics-vol016-csl2012/LIPIcs.CSL.2012.243/LIPIcs.CSL.2012.243.pdf#page=1)). Underneath all of these sits Church's theorem that β-equality is undecidable ([Lectures, p.4](https://disi.unitn.it/~bernardi/RSISE11/Papers/curry-howard.pdf#page=4)), which is what makes conversion for arbitrary programs undecidable in the first place.

disp is at the hard end of this ladder by construction. A type is an ordinary program that answers yes or no about a tree, built on the tree calculus (Barry Jay's reflective combinator calculus, where programs can inspect other programs), so the oracle is not "is T inhabited" but "does this recognizer program return true on this candidate", and running an arbitrary recognizer is Turing-complete. The set of accepted values and the set of refuted values are each only semi-decidable (run and see); a claim about every tree, "succ sends every Nat to a Nat", is not reachable by running alone. The gradual stream checker (GRADUAL.disp) makes the consequence concrete in its first two steps: the enumerated check of an arrow type on the first forty trees returns true for succ and false with a re-runnable witness for the pairing function, and only the false is a proof, the true being "no counterexample among the trees the budget reached"; a domain recognizer that loops on its second input hangs the native filter, which is why every later step runs under fuel. The verdict library (lib/verdict.disp) therefore already has the three outputs the complexity theory forces, Proved, Refuted with a witness, and Open (optionally carrying a reason), and states the contract a shortcut checker owes the honest enumerated run: Proved needs the run to pass, Refuted needs it to fail, Open is consistent with either.

The three verdicts are not symmetric under extension, and the asymmetry is the design principle that the rest of this note keeps returning to. Only a refutation can be monotone: if a prefix is refuted, every extension must still be refuted, and that holds only when the contradiction is stable, meaning no later input can repair it. The 2026 Semantic Prefix Oracles paper states the two contracts a prefix oracle owes a decoder, "safe pruning and dead-end freedom", proves the first for its implementation ("Theorem 2.4 (Safe pruning). Aufbau never rejects a prefix that has a witness. Proof. Every rejection is justified by a stable contradiction on every compatible branch." ([Kronlund-Drouault 2026, Thm 2.4](https://arxiv.org/html/2609.35425v1#S2.Thmtheorem4.p1.1.1))), and explains how undecided information must be handled: "prediction-time checks use only constraints already determined by the consumed prefix. Missing information can therefore delay a rejection, but it cannot create one." ([§2.3](https://arxiv.org/html/2609.35425v1#S2.SS3.p2.1)). The dual is explicitly not promised: "Dead-end freedom is a property of a grammar in addition to the oracle. A Live prefix has not contradicted the grammar, but it may still have no completion." The paper's example is plain simply typed lambda calculus with two distinct atomic types, where the prefix λf:A→B. f( is live but has no witness if the language has no closed term of type A ([§2.3](https://arxiv.org/html/2609.35425v1#S2.SS3.p3.1)). Dead-end freedom is recovered only under three grammar conditions, productivity, type coverage ("Every reachable type demand has a finite closed realizer") and left-to-right flow of obligations ([Thm 2.6](https://arxiv.org/html/2609.35425v1#S2.Thmtheorem6.p1.1.1)), and the paper claims none of them for its STLC instance. The PLDI 2025 type-constrained decoder reaches the same place from the other side: its automaton "satisfies the prefix property" when every reachable state can reach acceptance, and the price is stated outright: "Incompleteness exists because to ensure that our algorithms terminate, we do not cover high-order types that are less likely to occur in practice." ([Mündler et al. 2025, p.10](https://arxiv.org/pdf/2504.09246#page=10)). A Proved verdict for a prefix therefore requires dead-end freedom, and no real language guarantees it; in disp, where a type with no inhabitant is a legitimate type, it cannot hold in general.

Two further facts fix what Open must and must not be. First, an oracle that is incomplete (rejects valid programs) is actively harmful rather than merely conservative: a June 2026 study across seven models found that "Incompleteness pushes the model into low-probability regions of the program space, causing the generation to frequently time out, and reducing functional correctness by up to 97%." ([Biagiola et al. 2026, p.1](https://arxiv.org/pdf/2606.21619#page=1)). A step-budgeted checker that maps "ran out of budget" to "rejected" is exactly such an incomplete oracle, so Open must map to live, never to dead. Second, the cost half of disp's objective has its own trap: the Synquid synthesizer notes that "In the context of synthesis, termination concerns are impossible to ignore, since non-terminating recursive programs are always simpler than terminating ones" ([Synquid, p.2](https://arxiv.org/pdf/1510.08419#page=2)), so a size or step prior without a termination side-condition systematically prefers divergent candidates, and a budgeted recognizer that cannot finish on them will return Open rather than Refuted. The three-valued verdict is forced, Refuted is the only monotone one, and Open has to be treated as uninformative rather than as evidence either way.

## 2. Constrained decoding today: microsecond masks, one pruning contract, a distorted distribution

### 2.1 Grammar engines made the per-token mask a solved cost problem, by over-approximating

All production grammar-constrained decoding engines compute a per-token mask (a boolean over the vocabulary) from a character-level grammar by walking the vocabulary as a trie against an automaton or parser state, and they differ in which parser. Outlines compiles a regex to a finite automaton and indexes the vocabulary once by automaton state, "an algorithm that costs O(1) on average" ([Willard & Louf 2023, p.2](https://arxiv.org/pdf/2307.09702#page=2)). llguidance "implements a context-free grammar parser using Earley's algorithm on top of a lexer based on derivatives of regular expressions", computes the mask by trie traversal, and reports that "Mask computation takes approximately 50μs of single-core CPU time for a tokenizer with 128k tokens" with "no significant startup cost" ([llguidance README](https://github.com/guidance-ai/llguidance#technical-details)); its uncached mask for a typical JSON schema is about 1.5 ms, the average over a 2.5-million-token benchmark is under 50 µs, and under 1% of masks exceed 1 ms ([README, comparison](https://github.com/guidance-ai/llguidance#comparison-and-performance)). XGrammar (MLSys 2025) splits the vocabulary into context-independent tokens, precomputed per automaton state, and context-dependent ones checked at runtime, observing that the latter "account for only a minor proportion, amounting to less than 1% (1134 out of 128k)" for Llama-3.1 on JSON ([Dong et al. 2025, p.4](https://arxiv.org/pdf/2411.15100#page=4)); it measures **under 40 µs per token for JSON Schema and CFG (JSON), and under 200 µs for XML and Python DSL** ([p.9](https://arxiv.org/pdf/2411.15100#page=9)) and "nearly zero overhead in TPOT" end to end by overlapping mask generation with the forward pass ([p.10](https://arxiv.org/pdf/2411.15100#page=10)). XGrammar-2 (2026) targets grammars that change within a request, with an "Earley-based adaptive token mask cache, just-in-time compilation, and repetition state compression" ([Li, Dong et al. 2026, p.1](https://arxiv.org/pdf/2601.04426#page=1)). Koo, Liu and He reformulate detokenization as a finite-state transducer so that the token-level constraint is the character-level automaton composed with it ([Koo et al. 2024, p.3](https://arxiv.org/pdf/2407.08103#page=3)), report "a few microseconds" per step ([p.10](https://arxiv.org/pdf/2407.08103#page=10)), and restrict pushdown constraints to deterministic grammars, signalling an error otherwise ([p.6](https://arxiv.org/pdf/2407.08103#page=6)).

Soundness in these engines is bought by over-approximation, and the trade is stated. SynCode uses LR(1) parsers ("LR(1) parsers suffice for eliminating most syntax errors" ([Ugare et al. 2024, p.14](https://arxiv.org/pdf/2403.01632#page=14))) with an offline table from lexer states to masks, and says of its remainder handling: "we overapproximate the precise set of syntactically valid tokens. We make this choice to ensure that SynCode is sound for any length of accept sequences." ([p.11](https://arxiv.org/pdf/2403.01632#page=11)). It removes 96.07% of Python and Go syntax errors on average ([p.3](https://arxiv.org/pdf/2403.01632#page=3)); its offline mask store for Llama-2-7B took 113.72 seconds and 181 MB ([p.21](https://arxiv.org/pdf/2403.01632#page=21)). The common pattern is: never mask a token that could be valid, accept that some invalid tokens slip through and are caught later. Tokenizer alignment is a correctness issue rather than a speed detail: DOMINO (ICML 2024) measured that "naive constraining can reduce accuracy from 41.5% in the unconstrained case to 30.8%" on GSM8K with Mistral 7B ([Beurer-Kellner et al. 2024, p.3](https://arxiv.org/pdf/2403.06988#page=3)), defined the target property as "minimally invasive" (every valid output the unconstrained model could produce remains producible) ([p.2](https://arxiv.org/pdf/2403.06988#page=2)), and brought free-form JSON overhead to 4.21% with vocabulary-aligned subterminals ([p.9](https://arxiv.org/pdf/2403.06988#page=9)). Offline alignment cost is its own research line: Park, Zhou and D'Antoni (2025) report "17.71x faster offline preprocessing" where existing engines "require tens of minutes to preprocess common grammars" ([p.1](https://arxiv.org/pdf/2502.05111#page=1)). The 2023 slow end, for calibration, was a Grammatical Framework incremental parser whose per-token latency for one grammar was 0.5 s, far above the language model's forward pass ([Geng et al. 2023, p.18](https://arxiv.org/pdf/2305.13971#page=18)).

The one theory paper on this machinery (March 2026) formalizes grammar-constrained decoding "as a coupling between a Transformer-style next-token distribution and a reachability oracle over a pushdown system compiled from a CFG", proves that language-equivalent grammars induce identical masks, shows the packed-parse-forest cost is O(1) per token under right recursion but Θ(t²) under concatenation, and gives a lower bound: any sound, retrieval-efficient, parse-preserving online engine does Ω(t²) work per token on some constant-size CFG family ([Alpay & Senturk 2026, p.1](https://arxiv.org/pdf/2603.05540#page=1)). The practical reading is that per-token grammar checking is solved for grammars that fit a cache, the remaining budget items are offline compilation and the ambiguous-grammar tail, and the tail cannot be engineered away for all grammars.

### 2.2 Semantic decoders converge on safe pruning and decline dead-end freedom

Systems that enforce scope and types alongside syntax all adopt the same contract, with increasing formality over time, and all pay in decode time proportional to how much semantics they check per token. Synchromesh (ICLR 2022) abstracts the constraint as a completion engine with axioms ([Poesia et al. 2022, p.4](https://arxiv.org/pdf/2201.11227#page=4)) and builds the mask from "a decision procedure for membership in prefix-closure of the set L of all valid programs" ([p.5](https://arxiv.org/pdf/2201.11227#page=5)); it adds "an average of 8% overhead" with GPT-3 ([p.6](https://arxiv.org/pdf/2201.11227#page=6)) and lifts SQL validity from 43% to 72% ([p.7](https://arxiv.org/pdf/2201.11227#page=7)). PICARD (EMNLP 2021) rejects inadmissible tokens inside beam search in four modes, lexing, parsing, and parsing with scope guards, where a column reference obliges its table to be "eventually" in scope and "These guards are enforced eagerly in order to fail fast" ([Scholak et al. 2021, p.3](https://arxiv.org/pdf/2109.05093#page=3)); decoding went from 2.5 to 3.1 s per sample on an A100 ([p.4](https://arxiv.org/pdf/2109.05093#page=4)). Monitor-Guided Decoding (NeurIPS 2023) calls static analysis through the Language Server Protocol at trigger points, improves compilation rate by 21.77% to 24.69% relative ([Agrawal et al. 2023, p.7](https://arxiv.org/pdf/2306.10763#page=7)), states that its partial-program analyses "can be both imprecise (they can give incorrect suggestions) and incomplete (they can leave out correct suggestions)" ([p.10](https://arxiv.org/pdf/2306.10763#page=10)), and costs "a mean slowdown of 83.16% in decoding time for CodeGen-6B" ([p.21](https://arxiv.org/pdf/2306.10763#page=21)).

The PLDI 2025 type-constrained decoder is the strongest per-language result and the closest published analogue of "type checker as hard constraint, LLM as soft score". Its motivation is that "on average 94% of compilation errors result from failing type checks" in generated TypeScript ([Mündler et al. 2025, p.2](https://arxiv.org/pdf/2504.09246#page=2)); it builds "novel prefix automata and a search over inhabitable types, forming a sound approach to enforce well-typedness" ([p.1](https://arxiv.org/pdf/2504.09246#page=1)); it "reduces compiler errors by 74.8% and 56.0%" on HumanEval and MBPP against an ideal 9.0% and 4.8% from syntax-only constraining ([p.17](https://arxiv.org/pdf/2504.09246#page=17)), at **39.1% and 52.1% more median wall time** in an unoptimized Python implementation, with 99.4% of steps needing one sample-and-check iteration ([p.19](https://arxiv.org/pdf/2504.09246#page=19)). The 2026 Semantic Prefix Oracles paper separates the two contracts formally (section 1), proves safe pruning, proves dead-end freedom only under its three grammar conditions, proves decidability of prefix evaluation for finite grammars with regular terminals and productive nonterminals because "Earley parsing over a finite input has a finite chart of item cores" ([Prop 2.2](https://arxiv.org/html/2609.35425v1#S2.Thmtheorem2.p1.m6)), and validates differentially: "Across every prefix of 65 compiler-valid programs we observe zero false prunes. The semantic oracle localizes 25/30 invalid programs mid-stream, against 0/30 for a syntax-only oracle" against ocamlc and cc ([abstract](https://arxiv.org/html/2609.35425v1#abstract1.2.2)), with the author's caveat that "These are finite, hand-selected test cohorts, so the results validate rather than certify." ([§4.1](https://arxiv.org/html/2609.35425v1#S4.SS1.p1.1.2)). Its whole-input cost grows "smoothly and mildly superlinearly with expression size, at log–log slopes of roughly 1.1–1.4" and stays under about 130 ms on a six-core laptop for the largest inputs ([§4.1](https://arxiv.org/html/2609.35425v1#S4.SS1.p6.1.2)); no per-token figure is given.

The 2025–2026 fringe generalizes the realizability question or moves the verifier off the token axis. ChopChop "formulates this analysis as a realizability problem which is solved via coinduction" and demonstrates equivalence to a reference program and type safety as decoding constraints ([Nagy et al. 2025, p.1](https://arxiv.org/pdf/2509.00360#page=1)). Decode-Time Grammars (Jul 2026) treat scope as grammar refinement and "prove No-Ghost soundness for Γ-slotted fragments", so references are drawn from exactly the names available at that point ([Zhang et al. 2026, p.1](https://arxiv.org/pdf/2607.18357#page=1)). Decoding Time Verification (May 2026) runs full verifiers at structural boundaries with rollback instead of per token, taking C-to-Rust pass rate from 72.3% to 82.0% on Qwen3-4B ([Zhou et al. 2026, p.1](https://arxiv.org/pdf/2605.17626#page=1)); this is the pattern for a verifier that cannot be made incremental. AdapTrack adds backtracking so that constraints do not distort the model's intent ([Li et al. 2025, p.1](https://arxiv.org/pdf/2510.17376#page=1)), and SEM-CTRL runs token-level Monte Carlo tree search under Answer Set Grammars ([Albinhassan et al. 2026, p.1](https://arxiv.org/pdf/2503.01804#page=1)). The thing none of these does is run an arbitrary program as the type oracle: every verified type-aware decoder restricts itself to a decidable, terminating fragment (simply typed, monomorphic, no inference recursion, no higher-order types) precisely so that the oracle can answer per token.

### 2.3 Masking is a Doob transform with the wrong h

Masking the next-token distribution to allowed tokens and renormalizing does not sample "the model conditioned on the output being valid". Grammar-Aligned Decoding (NeurIPS 2024) names the missing factor: the expected future grammaticality c(w) of a prefix, "the probability that a continuation of w_{1:i} sampled from P lands in L(G)" ([Park et al. 2024, p.3](https://arxiv.org/pdf/2405.21047#page=3)), and shows that greedy masking "makes no attempt to integrate the model's likelihood to estimate expected future grammaticality, which can lead to substantial bias in the sampling distribution—i.e., every EFG such that c(w_{1:i}) > 0 is approximated by 1" ([p.4](https://arxiv.org/pdf/2405.21047#page=4)). Mass flows toward prefixes with few valid completions. Their ASAp algorithm learns the expected futures from repeated samples and provably converges, but "In some benchmarks, even after 2,000 iterations the KL divergence barely improves" ([p.10](https://arxiv.org/pdf/2405.21047#page=10)). The May 2026 "Future Validity" paper states the clean form: "the future-validity function Φ_t(y) = Pr_p[valid completion | y]" is "the missing correction statistic. The target distribution is a Doob transform of the base model with h = Φ, while local masking" sets Φ ≡ 1; on Dyck grammars with Qwen3-8B the total-variation gap "can reach 0.996", a one-step correction cuts it 14% at under 1% throughput cost, exact dynamic programming cuts it 97%, and "All fidelity claims are scoped to enumerable grammars and token tries" ([Nie et al. 2026, p.1](https://arxiv.org/pdf/2605.07698#page=1)). Alpay and Senturk derive sharp one-step KL and total-variation bounds for hard masking through the same transform ([p.1](https://arxiv.org/pdf/2603.05540#page=1)). Format restriction alone degrades reasoning even before any of this: "stricter format constraints generally lead to greater performance degradation in reasoning tasks" ([Tam et al. 2024, p.1](https://arxiv.org/pdf/2408.02442#page=1)).

Three families of fixes exist. Sequential Monte Carlo (SMC) treats generation "as posterior inference problems in a class of discrete probabilistic sequence models" at "a computational cost similar to that of beam search" ([Lew et al. 2023, p.1](https://arxiv.org/pdf/2306.03081#page=1)); the ICLR 2025 follow-up observes that locally constrained decoding "often introduces greedy approximations that badly distort the distribution" ([Loula et al. 2025, p.2](https://arxiv.org/pdf/2504.13139#page=2)) because "for most practical potential functions, the local and global product of experts do not define the same distribution" ([p.4](https://arxiv.org/pdf/2504.13139#page=4)), uses the masked model as the proposal, corrects with importance weights so the particle population is asymptotically exact, and puts expensive checks (running partial Python, checking SQL columns modulo aliasing) into the weights because they "cannot be efficiently encoded in logit masks", at a cost that "rarely rises above ∼30ms per token" ([p.9](https://arxiv.org/pdf/2504.13139#page=9)); the abstract reports small open models beating ones "over 8× larger" ([ICLR 2025 proceedings](https://proceedings.iclr.cc/paper_files/paper/2025/hash/a2d537e69a6c6638a3630eef835f07de-Abstract-Conference.html)). Its taxonomy of signals is the closest published framing of disp's situation: "some are cheap to compute (linting), others are more costly (simulations); some can be evaluated incrementally with each sampled token (language model critique), others provide sparser guidance (running code); some enforce binary hard constraints (type-checking), others yield soft continuous scores (scoring)" ([p.1](https://arxiv.org/pdf/2504.13139#page=1)). Adaptive weighted rejection sampling attacks the other cost, evaluating the constraint on every vocabulary token, with "an adaptive rejection sampling algorithm that typically requires orders of magnitude fewer constraint evaluations" and unbiased importance weights for SMC ([Lipkin et al. 2025, p.1](https://arxiv.org/pdf/2504.05410#page=1)); constrained adaptive rejection sampling records violating continuations in a trie and subtracts their mass so "the resulting samples exactly follow the constrained distribution" ([Parys et al. 2025, p.1](https://arxiv.org/pdf/2510.01902#page=1)). The second family learns the correction offline: SHIM observes that "the parser and lexer states that GCD tools already maintain carry a strong signal about future grammatical validity" and trains a correction conditioned on them, with no formal guarantee ([Özgü et al. 2026, p.1](https://arxiv.org/pdf/2608.10137#page=1)). The third distills the model into a tractable one: GeLaTo computes the conditional exactly in a hidden Markov model ([Zhang et al. 2023, p.1](https://arxiv.org/pdf/2304.07438#page=1)), Ctrl-G extends this to constraints given as deterministic finite automata ([Zhang et al. 2024, p.1](https://arxiv.org/pdf/2406.13892#page=1)); only this route is exact, and only for regular constraints, far from type checking.

For disp the identification is the load-bearing one in this note. Φ(prefix) is "the probability that a random completion type-checks". It is simultaneously the sampling correction that masking omits, the twist function of SMC, and the value function a search over partial programs wants (section 6.2 shows process reward models estimate exactly this quantity). An estimate of Φ is one object serving both roles. And the SMC framing is the one that already accommodates an expensive, possibly non-terminating oracle: cheap checks go in the proposal mask, the budgeted recognizer goes in the particle weight, with Refuted zeroing a particle and Open leaving its weight alone.

### 2.4 Inside the Earley oracle: items die only on stable, closed contradictions

The engine behind the Semantic Prefix Oracles paper (the author calls it aufbau; a single-author Rust crate of about 23,600 lines under src/, MIT, 160 commits from 2025-07-31 to 2026-09-25, read at commit 23f856c) is the most complete public implementation of a typed prefix oracle, and reading it answers the question the paper leaves abstract: where exactly is "stable contradiction" decided, and what does the verdict cost. A grammar file is EBNF productions plus inference-rule blocks with exactly three premise forms, membership x ∈ Γ, ascription Γ ⊢ e : τ, and equation τ₁ = τ₂, plus freshness ([GRAMMAR.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/GRAMMAR.md#L99-L128)); the rule parser rejects subtyping outright, "every relation is unification (=)" ([rule.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/rule.rs#L271-L275)). Each Earley item carries a demand, "the type its parent's premise ascribes to it, canonicalized" ([parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L44-L72)), and productions whose conclusion skeleton cannot meet the demand are not predicted at all ([parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L146-L186)). Node status is one of Exact, Prefix or Extensible ([arena.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/arena.rs#L92-L110)), and only an Exact node exports a declaration into the context its right siblings see ([paper, p.3](https://arxiv.org/pdf/2609.35425#page=3)).

The refutation gate is two conditions in one function. On a unification failure, the ascription step returns Unknown rather than Contradiction "if open || !failure_is_stable(norm, expected, actual)", with the doc comment explaining that holes can be instantiated without repairing a rigid clash, but a still-open node "can be replaced wholesale", so "there we must wait" ([domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L263-L297)). Stability itself is "norm.rules().is_empty() || (a.is_ground() && b.is_ground())": in the free theory "the only failures are rigid-rigid clashes and occurs-check violations, and both survive any substitution. With rewrite rules, only if both sides are ground: a hole can block a redex, so instantiating it may enable a rewrite that repairs the clash" ([normalize.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/normalize.rs#L146-L156)). The anti-monotone premise, freshness, is handled by waiting: a duplicate name is Unknown while the identifier is still open and Contradiction once it closes ([domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L491-L523)). The final verdict maps Contradiction to Lost, Partial to Live if the node is still open and to Lost if it is closed, and Success to Satisfied ([domain.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/domain.rs#L966-L1021)); a Lost item never becomes a node and never wakes a waiter ([parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L309-L361)). The architecture document states the invariant in one line: "The one runtime-side safety mechanism is the three-valued prune, and it only ever rejects; it cannot admit." ([architecture.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/docs/architecture.md#L159-L166)). The changelog records the move from gating on mere openness to gating on stability, with the effect that "let x : Bool = 1 is now dead at the 1" ([CHANGELOG.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/CHANGELOG.md#L23-L27)). Adding a rewrite theory weakens pruning to ground clashes, and the code acknowledges that unification modulo a theory with variables on both sides "needs narrowing (= search)" ([normalize.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/normalize.rs#L18-L24)).

"Incremental" here is an API property, not chart reuse. Each parse begins with a fresh arena and fresh tables ([parser.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/parse/parser.rs#L749-L755)); feed concatenates the token onto the input string, forks the parser and re-parses the whole extended string, committing only on success ([synth/mod.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/synth/mod.rs#L129-L152)); and mask over a candidate set is literally "try_feed each candidate and report whether it succeeded" ([synth/mod.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/synth/mod.rs#L154-L173)). Over a generation of n tokens the oracle work is therefore Θ(n × cost(prefix)), quadratic even where a single parse is linear, and the committed Criterion benchmarks already show per-parse cost growing superlinearly: a 7-token STLC application chain takes a median 1,152 µs, a 44-token imperative declaration block 1,987 µs ([chart_growth.csv](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/data/chart_growth.csv)). The plan describes today's decode loop as rejection sampling, "sample a token, screen 2–3 spellings via Synthesizer.mask, exclude and resample, bounded by max_retries (2048)", notes it "cannot become a vLLM logits processor, which wants one vectorized mask over the whole vocabulary per step", and lists the vocabulary-wide cached mask as open work ([PLAN.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/PLAN.md#L184-L204)). Dead-end freedom is not checked by code; the nearest thing is a sufficient-only certificate that classifies a grammar as syntactic, inhabited (every ascribed sort has a universal inhabitant such as ML's assert false, and every freshness binder is infinite) or merely sound with named blockers, and the module header says of the converse of safe pruning that it "is semantic inhabitedness (def:inhabited), PSPACE-complete in general" ([complete.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/complete.rs#L1-L59)). The STLC grammar is pinned as sound-only on exactly the paper's counterexample ([complete.rs tests](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/typing/complete.rs#L353-L383)), and a known-dead-end list records a prefix "Accepted today with no completion at all: the honest record of the oracle's imprecision" ([verdicts.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/validation/parseable/verdicts.rs#L125-L143)). One ignored test documents the opposite failure, a valid program's prefix judged dead ([ml.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/validation/parseable/ml.rs#L184-L232)), so the engine's "dead is unconditionally sound" claim should be read with that case in mind. The Rocq development leaves the soundness and completeness theorems Admitted pending a per-domain obligation "which does not exist yet for the real typing domain" ([OBLIGATIONS.md](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/verification/OBLIGATIONS.md#L12-L22)).

What disp can reuse is the discipline more than the code. The three-valued verdict with refutation gated on a stability predicate, the openness gate (never refute against a subterm whose right edge is still growing; evaluate only closed subterms plus holes), prediction-time filtering by a conclusion skeleton, and the testing regime: witness-checked must-stay-live lists where every entry carries a witness that "must extend its prefix and must type", because four stale cases once "sat here for weeks describing a soundness violation that did not exist" ([verdicts.rs](https://github.com/Unsuspicious-Industries/aufbau/blob/23f856c114adea05c6dd882efa1bd68a7f3e6747/src/validation/parseable/verdicts.rs#L173-L197)), token-boundary prefix monotonicity over valid programs, and whole-program differential checks against a trusted checker. What does not transfer is the foundation of Lost: it rests on first-order unification, where a rigid clash survives every substitution. In disp a type is a program deciding membership and a partial program has no term to clash; a sound semantic Refuted on a prefix needs a monotone abstraction of the partial program (a set of possible values, or an abstract value whose refinement only shrinks it) together with the guarantee that if the recognizer says no on the whole abstract set it says no on every refinement. Without such monotonicity there is no sound Lost, only Live. The prediction-time skeleton filter is cheap in aufbau only because conclusions are syntactic patterns; in disp the only cheap prediction-time filter is on the syntactic category of what can start at a position, which is what the chumsky probe below already gives.

### 2.5 The chumsky probe: a read-past-end flag gives sound dead verdicts for a PEG

Earlier this session the Rust parser-combinator library chumsky (version 0.14-dev, [repository](https://codeberg.org/zesterer/chumsky)) was tested as a prefix oracle for disp's own surface syntax, which is parsing-expression-grammar shaped (ordered choice, lookahead predicates). Six findings, all unpublished session results dated 2026-10-09. First, exact prefix liveness for a PEG is undecidable, because PEG emptiness is: "It is undecidable in general whether the language L(G) of an arbitrary parsing expression grammar G is empty" and whether an arbitrary grammar is complete ([Ford 2004, p.6](https://bford.info/pub/lang/peg.pdf#page=6)), with only well-formed (left-recursion-free) grammars guaranteed complete ([p.7](https://bford.info/pub/lang/peg.pdf#page=7)). Second, a custom input that records whether the parser ever read past the end of the prefix gives a sound "dead" verdict: if the parser never read past the prefix, its behaviour on every extension is identical to its behaviour on the prefix, so a failure is stable; whereas the usual heuristic, "the furthest error is at end of input", is unsound because the negation, try-map and custom-error combinators drop or replace that error. Third, the same flag is a mechanical "this node is exact" test, so a semantic predicate attached to a node may prune only if the flag is still unset when it runs, and must otherwise defer, which reproduces the paper's Exact versus Prefix evidence status by other means. Fourth, chumsky's check mode skips map and map-with closures but always runs try-map-with and validate, so any state mutation for scope tracking must live in the latter. Fifth, the measured cost was about 0.1 µs per token per full reparse, so quadratic re-checking of a 4,000-token program (about eight million token-parses in total) costs under a second, which puts a per-token syntactic probe in the same cost class as the grammar engines of section 2.1 without a vocabulary mask. Sixth, for disp, whose top-level is an unordered set of definitions with dependent types, "unbound identifier" is never a stable contradiction, because the binding may appear later in the file, so only syntactic contradictions and exact-node contradictions can prune at parse time, and dependent typing stays post-parse under a budget. The structural relation to the Earley engine is exact: both compute "dead" as "no reading survives to the end of input", but Earley keeps every alternative, so an ordered choice can never produce a false dead, whereas a PEG commits, which is why the PEG probe needs the read-past-end flag rather than the parser's own error position.

## 3. Program search: split the term language, learn from conflicts, order by a prior

### 3.1 Type-directed synthesis refines introduction forms downward and guesses eliminations upward

Every successful type-directed synthesizer splits the term language into two classes and runs them in opposite directions. Myth (PLDI 2015) states it as bidirectional type checking turned into a synthesis judgment: introduction forms (constructors, lambdas, matches) are refined top-down by pushing the goal type and the examples into subgoals, while elimination forms (variables, applications) are guessed by enumerating well-typed normal forms bottom-up, because "the ill-typed terms vastly outnumber the well-typed terms" ([Osera & Zdancewic 2015, p.1](https://www.cis.upenn.edu/~stevez/papers/OZ15.pdf#page=1)), and the guesser "only generates β-normal forms" ([p.2](https://www.cis.upenn.edu/~stevez/papers/OZ15.pdf#page=2)). The POPL 2016 follow-up proves that "examples can, in general, be interpreted as refinement types" and that example-directed synthesis is "proof search in a sequent calculus with intersection and union" types ([Frankle et al. 2016, p.1](https://www.cs.princeton.edu/~dpw/papers/type-synthesis-popl-2016.pdf#page=1)). Synquid (PLDI 2016) adds refinement types with a per-node satisfiability check so that a partial program is rejected before its holes are filled: its "round-trip type checking mechanism" combines bidirectional checking with "top-down propagation of overapproximate type information" ([Polikarpova et al. 2016, p.2](https://arxiv.org/pdf/1510.08419#page=2)), so that a wrong assignment "is discovered before the two arguments to insert are synthesized" ([p.5](https://arxiv.org/pdf/1510.08419#page=5)); it solved all 64 benchmarks, all but 7 within 5 seconds, and without its unsat-core minimization "37 out of 64 benchmarks time out" ([p.14](https://arxiv.org/pdf/1510.08419#page=14)). ReSyn (PLDI 2019) folds a resource bound into the same search, "eagerly rejecting incomplete programs that consume too many resources", while admitting that "both synthesis and resource analysis are undecidable in theory and expensive in practice" ([Knoth et al. 2019, p.1](https://arxiv.org/pdf/1904.07415#page=1)); that is disp's cost axis inside a type-directed search, a decade before disp. λ² combines "inductive generalization, deduction, and enumerative search", using deduction both to refute hypotheses and to infer new examples for holes, and guarantees "the least-cost program in our language to fit the examples" ([Feser et al. 2015, p.1](https://www.cs.utexas.edu/~swarat/pubs/pldi15.pdf#page=1)). InSynth (PLDI 2013) is the earliest clean instance of disp's exact objective, type inhabitation ranked by additive weights: "we introduce weights to guide the search and rank the presented solutions" ([Gvero et al. 2013, p.2](https://lara.epfl.ch/~kuncak/papers/GveroETAL13CompleteCompletionTypesWeights.pdf#page=2)), the weight of a term being the sum of the weights of its components ([p.5](https://lara.epfl.ch/~kuncak/papers/GveroETAL13CompleteCompletionTypesWeights.pdf#page=5)).

Since 2019 the frontier has been to replace one expensive exact check per candidate with a cheap abstraction refined only on failure. Hoogle+ introduces "type-guided abstraction refinement (TYGAR)": search a graph over abstract types by reachability, and when a candidate fails the real type checker, use the proof of untypeability to refine the abstraction ([Guo et al. 2020, p.2](https://arxiv.org/pdf/1911.04091#page=2)); it finds a well-typed program for 43 of 44 queries within 60 seconds, the first "within 1.4 seconds on average" ([p.1](https://arxiv.org/pdf/1911.04091#page=1)). Hectare encodes the shared type variables across argument positions as equality constraints on tree automata paths ([Koppel et al. 2022, p.1](https://arxiv.org/pdf/2206.07828#page=1)), reduces the automaton statically before enumeration, and "is able to solve 88% of synthesis problems in the combined benchmark suite compared to only 64% by Hoogle+", 8× faster on commonly solved ones with a tenth of the code ([p.3](https://arxiv.org/pdf/2206.07828#page=3)). Burst makes bottom-up search work for recursive programs by evaluating recursive calls angelically and strengthening the specification in a counterexample loop ([Miltner et al. 2022, p.2](https://arxiv.org/pdf/2107.06253#page=2)), solving 96% of the Myth suite from examples and outperforming Leon (76%) and Synquid (49%) on logical specifications ([p.3](https://arxiv.org/pdf/2107.06253#page=3)). Smyth propagates examples backward through partially evaluated sketches and needs "66% of the number of expert examples required by Myth" ([Lubin et al. 2020, p.1](https://arxiv.org/pdf/1911.00583#page=1)). The combinatory-logic lineage treats synthesis literally as type inhabitation, and its 2023 result draws the decidability line sharply: in plain finite combinatory logic "inhabitant sets correspond to regular tree languages", adding decidable predicates makes inhabitation undecidable, and a tree-automata fragment restores it ([Dudenhefner et al., TYPES 2023, p.1](https://drops.dagstuhl.de/storage/00lipics/lipics-vol303-types2023/LIPIcs.TYPES.2023.2/LIPIcs.TYPES.2023.2.pdf#page=1)).

The pattern across all of these is: decompose top-down while the goal type is informative, enumerate bottom-up only for elimination forms, in normal form, against an inhabitation oracle, and check partial programs with an over-approximation before their holes are filled. For disp, where the type is a recognizer program, the direct analogue of "refinement" is running the recognizer on the partially built tree with holes treated angelically (Burst) or over-approximately (Synquid's round trip); the recognizer need only reject some partial trees early for the pruning to pay. No system was found that combines a dependent-type inhabitation oracle with a learned enumeration prior; the nearest are the combinatory-logic synthesizers (intersection types, no learning) and Hazel's 2024 work, which hands the hole's type to an LLM rather than enumerating (section 4.4).

### 3.2 Conflict-driven learning is the direct precedent for "reify the conflict"

The optimizer design document (research/OPTIMIZER.typ) describes its loop as: enumerate per-hole candidate streams ordered by a prior, superpose them (run all candidates in one shared network, forking only at the holes), reduce the goal recognizer, collapse, and on an empty collapse "reify the conflict" into a witness (tree position, expected type, actual type) from which a pruning predicate is learned. Neo (PLDI 2018) did this for synthesis by importing conflict-driven clause learning from SAT solvers: "Given a spurious program that violates the desired specification, our synthesis algorithm identifies the root cause of the conflict and learns new lemmas that can prevent similar mistakes in the future. Specifically, we introduce the notion of equivalence modulo conflict" ([Feng et al. 2018, p.1](https://www.cs.utexas.edu/~isil/pldi18-neo.pdf#page=1)). A failing partial program becomes an SMT formula, its minimal unsatisfiable core names the components responsible, and every component whose specification is interchangeable in that core is pruned at the same positions, so one failure rules out a family. Neo solved "90% of these benchmarks with an average running time of 19 seconds, whereas Morpheus solves 64% with an average running time of 68 seconds", and the ablation with depth-first search and a random decider "only solves 10%" ([p.11](https://www.cs.utexas.edu/~isil/pldi18-neo.pdf#page=11)). Concord (CAV 2020) then made the conflicts a training signal: synthesis is an MDP whose actions are grammar productions, an off-line policy guides the search, and because the deduction engine's conflict analysis yields "feedback about states that have not been explored", it uses an off-policy policy-gradient update ([Chen et al. 2020, p.2](https://www.cs.utexas.edu/~isil/concord.pdf#page=2)); it "solves 15% more benchmarks compared to Neo... while improving synthesis time by 8.71× on benchmarks that can be solved by both tools" ([p.1](https://www.cs.utexas.edu/~isil/concord.pdf#page=1)). Blaze is the abstract-interpretation sibling: find a program consistent with the examples under abstract semantics, check concretely, and on failure build a "proof of incorrectness" whose predicates refine the abstraction so the proof rules out other spurious programs too, with "a 90x speed-up over Prose" on matrix tasks ([Wang et al. 2018, p.1](https://arxiv.org/pdf/1710.07740#page=1)); Atlas learns the abstract domains and transformers from training problems instead of asking an expert for them ([Wang et al. 2018, p.1](https://arxiv.org/pdf/1804.04152#page=1)).

Nothing found in 2024–2026 extends explicit conflict learning (unsat core plus lemma) beyond Neo and Concord; the recent "learning to prune" work is a just-in-time grammar re-estimated from partial solutions (Probe, solving 91 of 140 SyGuS problems against 44 for the baseline and 50 for Euphony ([Barke et al. 2020, p.3](https://arxiv.org/pdf/2010.08663#page=3))) or metric-based (Merlin's oriented metrics, "27 times faster than DryadSynth" on bitvectors ([Merlin 2025, p.2](https://arxiv.org/pdf/2511.02491#page=2))). That absence is itself a finding: the community moved to learned priors and LLM proposals. Three mappings matter for disp. Neo's decide, deduce, learn is sample the next hole filler from the prior, run the recognizer on the partial tree, reify the failure into a lemma. Equivalence modulo conflict needs comparable specifications; Neo has first-order attribute formulas, disp has a recognizer's rejection trace at a tree position, so the analogue is "two candidate subtrees are equivalent modulo this conflict if the rejection trace does not depend on how they differ", which a budgeted recognizer could establish by replaying with the subtree abstracted. And Concord's lesson is that a conflict is worth more as training signal than as a lemma: the lemma prunes once, the policy update prunes forever for that distribution. The termination theory carries over too: CEGIS, Neo's lemmas and disp's conflict witnesses are all instances of oracle-guided inductive synthesis, for which "When the concept class is infinite size, termination of CEGIS is not guaranteed", and with unbounded memory minimal counterexamples give no more power than arbitrary ones ([Jha & Seshia 2017, p.3](https://arxiv.org/pdf/1505.03953#page=3)); with a finite lemma store, which is the regime a real optimizer is in, structured witnesses do help.

### 3.3 Learned priors: generate each candidate once, in non-increasing probability

There are four tested ways to splice a learned prior into an exhaustive enumerator. The first reorders a complete search and keeps completeness: DeepCoder trains a network "to predict properties of the program that generated the outputs from the inputs" and uses the predictions to sort and gate depth-first search ([Balog et al. 2017, p.1](https://arxiv.org/pdf/1611.01989#page=1)); Euphony learns a probabilistic higher-order grammar from solved easier problems and enumerates "programs in order of their likelihood" ([Lee et al. 2018, p.1](https://www.cis.upenn.edu/~alur/PLDI18.pdf#page=1)) by A* over sentential forms ([p.3](https://www.cis.upenn.edu/~alur/PLDI18.pdf#page=3)), solving 236 of 405 test problems against EUSolver's 87, with the ablation "A*+PHOG, Uniform+PHOG, A*+PCFG, and Uniform+PCFG are able to solve 236, 209, 133, 22 instances, respectively" ([p.12](https://www.cis.upenn.edu/~alur/PLDI18.pdf#page=12)); the higher-order grammar itself conditions a production on learned context beyond the parent nonterminal ([Bielik et al. 2016, p.1](http://proceedings.mlr.press/v48/bielik16.pdf#page=1)). Neural-guided deductive search gates PROSE's witness-function decomposition with a learned branch-and-bound scorer, "up to 12× speed-up" ([Kalyan et al. 2018, p.1](https://arxiv.org/pdf/1804.01186#page=1)). The second reweights bottom-up enumeration: TF-Coder's per-operation weights from learned models solve 63 of 70 real tasks in 5 minutes ([Shi et al. 2022, p.1](https://arxiv.org/pdf/2003.09040#page=1)); Bustle re-weights intermediate values using property signatures ([Odena et al. 2021, p.1](https://arxiv.org/pdf/2007.14381#page=1)); Bee Search points out that rounding costs breaks best-first order and searches the abstract space of cost tuples instead ([Ameen & Lelis 2023, p.2](https://arxiv.org/pdf/2310.04327#page=2)). The third lets the policy be the enumerator: CrossBeam trains "a hands-on search policy for bottom-up synthesis, instead of relying on a combinatorial search algorithm" ([Shi et al. 2022, p.1](https://arxiv.org/pdf/2203.10452#page=1)), solves 62% more tasks than Bustle and considers "about 20× fewer candidate programs" ([p.2](https://arxiv.org/pdf/2203.10452#page=2)), and LambdaBeam extends this to constructing lambdas represented by execution behaviour ([Shi et al. 2023, p.1](https://arxiv.org/pdf/2306.02049#page=1)); the price is losing the completeness that makes conflict lemmas sound. The fourth, since 2024, is an LLM as prior for an exhaustive enumerator: Li, Parsert and Polgreen find prompting alone solves roughly 49% of SyGuS, build a probabilistic grammar from the LLM's often-wrong guesses, re-prompt during enumeration with partial enumerations and counterexamples ([Li et al. 2024, p.3](https://arxiv.org/pdf/2403.03997#page=3)), and beat cvc5 "solving 73 more benchmarks" ([p.16](https://arxiv.org/pdf/2403.03997#page=16)); HYSYNTH fits a context-free surrogate to the LLM's output distribution and guides bottom-up search with it ([Barke et al. 2024, p.2](https://arxiv.org/pdf/2405.15880#page=2)).

The theory of approach one is Fijalkow et al. (AAAI 2022): define the loss of a search as the expected number of programs enumerated before the solution under the predicted distribution; an algorithm is loss optimal iff it generates each program once in non-increasing probability; "The Heap Search algorithm is loss optimal" and is related to Euphony's A*, both being loss optimal; a dichotomy theorem characterizes when sampling is loss optimal; and a grammar splitter partitions the distribution so parallel workers never duplicate a program ([Fijalkow et al. 2022, p.2](https://arxiv.org/pdf/2110.12485#page=2), [p.4](https://arxiv.org/pdf/2110.12485#page=4), [p.6](https://arxiv.org/pdf/2110.12485#page=6)). For disp, "candidate streams ordered by a prior (size, library frequency, an LLM's logits)" is this distribution-based search, and the theorem says each stream should be loss optimal, which bucketing the prior into integer cost classes forfeits. Euphony's 236 versus 133 is the strongest single data point that a context-conditioned prior matters more than the search algorithm; a prior conditioned on the hole's expected type is the natural step beyond syntactic context.

### 3.4 Library learning shortens solutions and reshapes the prior, when the reuse is real

DreamCoder (PLDI 2021) made library learning a Bayesian loop: wake searches for programs under the current library guided by a recognition network, sleep-abstraction refactors found programs into reusable primitives, and sleep-dreaming retrains the recognizer on programs sampled from the library ([Ellis et al. 2021, p.1](https://arxiv.org/pdf/2006.08381#page=1)); on a text-editing suite it solved 3.7% of problems before learning and 84.3% after. Stitch (POPL 2023) made the abstraction step "3-4 orders of magnitude faster" with "2 orders of magnitude less memory" by synthesizing abstractions top-down under branch-and-bound on a compression utility ([Bowers et al. 2023, p.1](https://arxiv.org/pdf/2211.16605#page=1)); babble made it precise with e-graphs and anti-unification so abstractions common up to rewriting are found ([Cao et al. 2023, p.2](https://arxiv.org/pdf/2212.04596#page=2)), which is the right candidate generator when candidates are equal modulo rewriting, as tree-calculus programs often are. LILO (ICLR 2024) swaps the enumerator for an LLM and documents the catch: "naively providing a LLM with Stitch abstractions measurably degraded its ability" to use them, which motivated a step that names and documents each abstraction ([Grand et al. 2024, p.2](https://arxiv.org/pdf/2310.19791#page=2)). The October 2024 audit of two celebrated LLM library learners found that "direct reuse is negligible" and that self-correction and self-consistency, not reuse, produced the reported gains ([Berlot-Attwell et al. 2024, p.1](https://arxiv.org/pdf/2410.20274#page=1)). The 2026 critique is that "Existing library learning algorithms compress past tasks retrospectively" when abstractions should be chosen to compress future tasks ([Prospective Compression 2026, p.1](https://arxiv.org/pdf/2605.09985#page=1)). The two measurable effects on a search space are shorter solutions, which a size-ordered enumerator reaches sooner, and a changed prior, where library frequency becomes a feature; for a symbolic enumerator the library helps unconditionally, for an LLM prior only with names and documentation, and any claimed gain must be checked for actual reuse. An optimizer that learns abstractions from its own trace is exposed to the retrospective-compression overfit.

### 3.5 LLM-era verified loops: the gate works, the generator games it, feedback plateaus

The 2024–2026 record of language models generating code against a verifier gives three quantities disp needs: what fraction of a budget survives a hard gate, how much error feedback helps, and how the gate gets gamed. On the September 2025 vericoding benchmark of 12,504 formal specifications, "LLM vericoding worked best on Dafny (82.2%), followed by Verus (44.2%) and Lean (26.8%)" as a union over nine models with five repair attempts per task ([Bursuc et al. 2025, p.7](https://arxiv.org/pdf/2509.22908#page=7)); on the February 2026 AlgoVeri benchmark of 77 classical algorithms with identical contracts across the three languages, "even Gemini-3 Flash using a 15-round repair budget achieves only 40.3% full correctness in Dafny and 24.7% in Verus. In Lean, the success rate drops to 7.8%" ([Zhao et al. 2026, p.4](https://arxiv.org/pdf/2602.09464#page=4)). The spread tracks verifier automation (SMT-automated Dafny, tactic-level Lean) rather than model quality. Error feedback helps but saturates fast: on DafnyBench (June 2024) "the best models succeeded on the first try about 54%, with rapidly diminishing returns after that, approaching a plateau about 65% for n ∼ 5" ([Loughridge et al. 2024, p.5](https://arxiv.org/pdf/2406.08467#page=5)); Goedel-Prover-V2 (Aug 2025) goes from 88.1% to 90.4% on miniF2F with two rounds of compiler-guided self-correction and reports that "removing compiler feedback significantly lowers performance" ([Lin et al. 2025, p.11](https://arxiv.org/pdf/2508.03613#page=11), [p.9](https://arxiv.org/pdf/2508.03613#page=9)). Gaming is universal where unguarded. AlphaVerus (ICML 2025), which lets a Llama-70B produce verified Verus for 33% of HumanEval with no fine-tuning ([Aggarwal et al. 2024, p.3](https://arxiv.org/pdf/2412.06176#page=3)), documents that "Without filtering mechanisms, the model learns to exploit verification by increasingly using assume (false) statements. This snowballing effect shows the importance of critique models in preventing reward-hacked solutions", after which the model found debug attributes allowing infinite loops and trivial specifications; its defenses are a string matcher, an LLM judge for spec alignment, and an adversarial exploit model that tries trivial implementations and discards the translation if one verifies ([p.9](https://arxiv.org/pdf/2412.06176#page=9)). AutoVerus's AST-level check found that 326 of 2,637 candidates (12.4%) were unsafe and filtered them ([Yang et al. 2024, p.15](https://arxiv.org/pdf/2409.13082#page=15)); DafnyBench counts a program as solved only if the model "does not use {:verify false} or {assume false} to 'cheat.'" ([p.15](https://arxiv.org/pdf/2406.08467#page=15)). On the specification side, Verina (2025) reports the best model at 72.6% code correctness, 52.3% specification soundness-and-completeness and below 4.9% proof success ([Ye et al. 2025, p.2](https://arxiv.org/pdf/2505.23135#page=2)), and CLEVER, where the generated spec must be proven equivalent to a hidden one, finds frontier models "can only solve up to 1/161 end-to-end verified code generation problem" ([Thakur et al. 2025, p.2](https://arxiv.org/pdf/2505.13938#page=2)). Section 6.7 collects the exploits and the defenses that held.

The evolutionary systems are the purest instance of "hard evaluator, frozen proposer". FunSearch scopes itself to "problems admitting an efficient 'evaluate' function" ([Romera-Paredes et al. 2023](https://www.nature.com/articles/s41586-023-06924-6#Sec1-content)), keeps diversity with an islands model ([Sec. 6](https://www.nature.com/articles/s41586-023-06924-6#Sec6)), and found a cap set of size 512 in dimension 8 ([Fig. 4](https://www.nature.com/articles/s41586-023-06924-6#figure-4-desc)). AlphaEvolve (June 2025) found a 48-multiplication algorithm for 4×4 complex matrices, "the first improvement, after 56 years, over Strassen's algorithm in this setting" ([Novikov et al. 2025, p.1](https://arxiv.org/pdf/2506.13131#page=1)), rediscovered the best known construction in 75% of 50 open problems and improved it in 20% ([p.10](https://arxiv.org/pdf/2506.13131#page=10)), allows "on the order of 100 compute-hours to evaluate any new solution" with cascades of test cases of increasing difficulty ([p.8](https://arxiv.org/pdf/2506.13131#page=8)), and names its limit: "The main limitation of AlphaEvolve is that it handles problems for which it is possible to devise an automated evaluator." ([p.21](https://arxiv.org/pdf/2506.13131#page=21)). A boolean type checker is a degenerate such evaluator, and disp's "checker times cost" is AlphaEvolve's multi-score setup with one score hard-gated; the Georgiev–Gómez-Serrano–Tao–Wagner run on 67 problems couples AlphaEvolve to AlphaProof after the fact ([Georgiev et al. 2025, p.1](https://arxiv.org/pdf/2511.02864#page=1)), the first published evolutionary constructor feeding a proof-gated verifier. A methodological warning from September 2026: re-running three evolutionary strategies over a full seeds-by-iterations grid, "On one task the strategy that looks worst at one seed is best at forty seeds" ([Oved et al. 2026, p.1](https://arxiv.org/pdf/2609.19799#page=1)).

Neural proof search spent the verifier's bit in three successive ways. In 2020–2024 tree search, the verifier pruned invalid tactics and a critic was trained on search outcomes: GPT-f closed 56.22% of held-out Metamath proofs ([Polu & Sutskever 2020, p.2](https://arxiv.org/pdf/2009.03393#page=2)); HyperTree Proof Search reached 65.4% then 82.6% with online training ([Lample et al. 2022, p.1](https://arxiv.org/pdf/2205.11491#page=1)) and found that hard 0/1 targets on internal nodes were worse than no critic ([p.13](https://arxiv.org/pdf/2205.11491#page=13)); AlphaProof's network emits "a list of N promising tactics to try and a value estimating proof difficulty" for the tree search ([Hubert et al. 2025, Fig. 1](https://www.nature.com/articles/s41586-025-09833-y#figure-1-desc)), trained on about 80 million auto-formalized problems ([Nature 2025](https://www.nature.com/articles/s41586-025-09833-y#ref-link-section-d157923345e988)). In 2024–2025 whole-proof RL, the verifier became a binary terminal reward with no search at inference beyond sampling: DeepSeek-Prover-V2 uses "binary correct-or-incorrect feedback as the primary form of reward supervision" ([Ren et al. 2025, p.5](https://arxiv.org/pdf/2504.21801#page=5)); Kimina-Prover reached "80.7% with pass@8192" ([Wang et al. 2025, p.2](https://arxiv.org/pdf/2504.11354#page=2)) with "All proofs... generated without any prover feedback during training and test" ([Kimina README](https://github.com/MoonshotAI/Kimina-Prover-Preview#key-ingredients-of-kimina-prover-preview)). In 2025–2026 agents feed the verifier's error text and proved lemmas back in a loop and decompose into subgoals: Seed-Prover went from 201 to 331 of 657 PutnamBench problems between its light and medium settings ([Chen et al. 2025, p.9](https://arxiv.org/pdf/2507.23726#page=9)); Hilbert reached 99.2% on miniF2F and 462 of 660 PutnamBench ([Varambally et al. 2025, p.1](https://arxiv.org/pdf/2509.22819#page=1)); the January 2026 leaderboard snapshot ranks Aleph Prover at 668 of 672 under a $1,400-per-problem cap, Seed-Prover 1.5 at 581, Hilbert at 462, Goedel-Prover-V2 at 86 and STP at 8 ([Minimal Agent 2026, Table 2](https://arxiv.org/pdf/2602.24273#page=14)), observing that "the leading provers are agents that generate full proofs combined with an iterative proof refinement strategy based on the Lean compiler feedback" ([p.2](https://arxiv.org/pdf/2602.24273#page=2)); Leanstral 1.5 (vendor post, July 2026) reports 587 of 672 ([Mistral 2026](https://mistral.ai/news/leanstral-1-5/#tooltip-7db3c16d-1e27-4891-8038-9601dbf09b96)). Budgets exploded as scores saturated, from pass@32 to pass@42,000 and to dollars per problem, which is the unit disp's cost-weighted objective should expect. The decomposition trend, sketches with placeholder holes closed by a smaller prover, lemma libraries, recursive subgoals, is a typed-hole search: the checker accepts a sketch with holes and each hole becomes an independent subproblem, the proof-side analogue of per-hole candidate streams.

### 3.6 Tree search with a verifier on partial programs is an optimistic bound, and it worked

VerMCTS (2024) is the only published system that puts a verifier on partial programs inside the search as the expansion filter: it "uses a logical verifier in concert with an LLM to guide a modified Monte Carlo Tree Search... by checking partial programs at each step to estimate an upper bound on the value function", where a prefix that verifies but is incomplete scores +1 and a rejected one is not added and marks its parent −1 ([Brandfonbrener et al. 2024, p.1](https://arxiv.org/pdf/2402.08147#page=1)). With a frozen 34B model and no training, "we see about a 30% absolute improvement in pass@5000 for VerMCTS relative to whole sampling. This amounts to a 4x relative improvement on Dafny and on Coq, whole sampling does not even get a pass rate above 0 at this budget" ([p.7](https://arxiv.org/pdf/2402.08147#page=7)). The gain came entirely from pruning, with no learned value; this is the baseline a stream checker on partial disp programs should at least match. Most code MCTS uses test pass rate instead (PG-TD's planning objective ([Zhang et al. 2023, p.2](https://arxiv.org/pdf/2303.05510#page=2)); RethinkMCTS, which lifted GPT-3.5 on HumanEval from 70.12 to 89.02 by rewriting erroneous thoughts from execution feedback ([2024, p.6](https://arxiv.org/pdf/2409.09584#page=6))), and the verifier-as-reward variants are the exceptions with soundness guarantees on the output. Hazel's typed-hole work supplies the other half: handing the LLM the hole's expected type and in-scope headers raised StarCoder2's correct-solution rate "by an order of magnitude" on five from-scratch programs, with headers adding "an additional 50% increase in relative performance" and two cases degrading ([Blinn et al. 2024, p.19](https://arxiv.org/pdf/2409.00921#page=19)), evidence that the expected type is the single most valuable constraint to expose to a generator, at a scale that establishes direction rather than magnitude. No paper was found that uses a dependently typed hole, an expected type that is a proposition, to filter LLM expansions step by step in a general-purpose language.

## 4. Type systems already have a don't-know, and it is always monotone

### 4.1 Gradual typing buys consistency checking and a monotonicity law, and pays for both

The unknown type is the first formal "don't know" at the type level. In Siek and Taha's 2006 formulation "The unknown portions of a type are indicated by ?" and "The job of the static type system is to reject programs that have inconsistencies in the known parts of types" ([Siek & Taha 2006, p.2](http://scheme2006.cs.uchicago.edu/13-siek.pdf#page=2)); everything else is deferred to a run-time cast, and a failed cast is attributed by blame so that "well-typed programs can't be blamed" ([Wadler & Findler 2009, p.1](https://homepages.inf.ed.ac.uk/wadler/papers/blame/blame.pdf#page=1)). The design law is the gradual guarantee: "if a gradually typed program is well typed, then removing type annotations always produces a program that is still well typed" ([Siek et al. 2015, p.6](https://drops.dagstuhl.de/storage/00lipics/lipics-vol032-snapl2015/LIPIcs.SNAPL.2015.274/LIPIcs.SNAPL.2015.274.pdf#page=6)). Abstracting Gradual Typing gives ? an abstract-interpretation reading, the abstraction of a set of static types with "Proposition 3 (α is Sound). If T̂ is not empty, then T̂ ⊆ γ(α(T̂))", and derives run-time checks as "evidence for consistent judgments during proof reduction" ([Garcia et al. 2016, p.1](https://www.cs.ubc.ca/~rxg/agt.pdf#page=1)). The costs are measured and spectral: sound implementations "suffer from performance overheads due to these checks" ([Takikawa et al. 2016, p.1](https://www2.ccs.neu.edu/racket/pubs/popl16-tfgnvf.pdf#page=1)); and "The literature on gradual typing presents three fundamentally different ways of thinking about the integrity of programs that combine statically typed and dynamically typed code", each with its own soundness theorem ([Greenman & Felleisen 2018, p.1](https://www2.ccs.neu.edu/racket/pubs/icfp18-gf.pdf#page=1)), so "what a passed check means" is a design knob. New and Ahmed refine the dynamic guarantee into an error-approximation order where "embedding-projection pairs (ep pairs) are to graduality what relations are to parametricity" ([New & Ahmed 2018, p.1](https://arxiv.org/pdf/1807.02786#page=1)), and Gradual Type Theory proves that if βη laws hold then the cast semantics is forced ([New et al. 2019, p.1](https://arxiv.org/pdf/1811.02440#page=1)). The transfer to disp is one sentence: ? is a don't-know resolved by evidence at run time, Open is a don't-know resolved by more budget, and the gradual guarantee is the template for the law a budgeted checker must satisfy, monotone in precision or budget, with the Greenman–Felleisen spectrum as the warning that any claim "the cheap checker agrees with the canonical one" must say which soundness it preserves.

### 4.2 The fire triangle says the don't-know cannot be eliminated for free

Gradual dependent types make the price exact. The 2022 GCIC paper proves "a gradual type theory cannot satisfy at the same time normalization, graduality, and conservativity with respect to CIC" ([Lennon-Bertrand et al. 2022, p.5](https://arxiv.org/pdf/2011.10618#page=5)), the quintessential witness being Ω, which becomes well typed and divergent once ? → ? is consistent with ?. Each system drops a corner: one variant "is not normalizing", one satisfies normalization and graduality but is conservative only over a theory that "loses the closure of universes under dependent product" ([p.15](https://arxiv.org/pdf/2011.10618#page=15)), and one keeps normalization and conservativity but "does not fully validate G", losing even the static gradual guarantee for some terms ([p.16](https://arxiv.org/pdf/2011.10618#page=16)). GRIP takes a fourth path, graduality "for a large and well-defined class of terms" (the self-precise ones) while "being normalizing and a conservative extension of CIC", with precision internalized so the theory can state its own graduality ([Maillard et al. 2022, p.1](https://arxiv.org/pdf/2209.00975#page=1)). The system nearest disp's budget is GDTL's approximate normalization: "compile-time normalization is approximate but total, while runtime execution is exact, but may fail or diverge. We prove that GDTL has decidable typechecking", and the authors "were led to establish a novel normalization gradual guarantee that captures the monotonicity of approximate normalization with respect to imprecision" ([Eremondi et al. 2019, p.1](https://arxiv.org/pdf/1906.06469#page=1)); the GCIC paper characterizes its cost, approximate normalization "always produces ?_A as a result of going through imprecision and back" ([GCIC, p.15](https://arxiv.org/pdf/2011.10618#page=15)), information lost rather than normalization lost. Gradual propositional equality carries evidence: each proof "is accompanied by a term that is at least as precise as the equated terms", raising errors only when "two equated terms are undeniably inconsistent" ([Eremondi et al. 2022, p.1](https://arxiv.org/pdf/2205.01241#page=1)), the three-valued pattern at the level of equality proofs. Gradual verification moves ? into specification formulas with exactly the operational shape of accepting an Open verdict: "an imprecise specification can be optimistically strengthened (in non-contradictory ways) by the verifier to support proof goals. Wherever such strengthenings occur, dynamic checks are inserted to preserve soundness" ([DiVincenzo et al., Gradual C0, p.2](https://arxiv.org/pdf/2210.02428#page=2)). Indexed inductive types are the 2024 frontier where "the standard encodings... break in the presence of gradual features" ([Malewski et al. 2024](https://icfp24.sigplan.org/details/icfp-2024-papers/21/Gradual-Indexed-Inductive-Types#c2371058bcb9b31dd10e115e7f712708)); no 2025–2026 gradual dependent type paper surfaced in two searches, so the verified state of the art is GRIP (2022) and that abstract (2024). disp's budgeted check is a fourth compromise the triangle already anticipates: the type language need not normalize, the checker is total because of fuel, and the don't-know is GDTL's result. The theorem to prove for the stream checker is the normalization gradual guarantee with budget playing precision: budget k' ≥ k yields a verdict at least as definite and never contradictory. GRIP's self-precise class is the right target for a sub-language where verdicts are exact within a bounded budget.

### 4.3 Soft and probabilistic typing treat the checker as a filter, never as a likelihood

Soft typing (Cartwright and Fagan 1991; the ACM text is blocked and is cited here through a verified explainer) never rejects a program: a soft type system must "accept all syntactically correct programs as input; produce equivalent, memory-safe programs as output; and be unobtrusive", inserting run-time checks where the inferred type cannot be proved ([Greenman 2017](https://prl.khoury.northeastern.edu/blog/2017/04/28/what-is-soft-typing/#what-are-the-design-criteria)). The machine-learned type-inference line quantifies confidence but keeps the checker exact: JSNice predicts types as a CRF's MAP assignment, correct 81% of the time ([Raychev et al. 2015, p.1](https://files.sri.inf.ethz.ch/website/papers/jsnice15.pdf#page=1)); LambdaNet outputs "a probability distribution of types for each missing annotation" ([Wei et al. 2020, p.3](https://arxiv.org/pdf/2005.02161#page=3)); TypeWriter "invokes a gradual type checker with different combinations of the predicted types, while navigating the space of possible type combinations in a feedback-directed manner" and fully annotates 14% to 44% of files "while ensuring type correctness" ([Pradel et al. 2020, p.1](https://arxiv.org/pdf/1912.03768#page=1)), the clearest precedent for generator proposes, checker decides; Typilus "confidently predicts types for 70% of all annotatable symbols; when it predicts a type, that type optionally type checks 95% of the time" ([Allamanis et al. 2020, p.1](https://arxiv.org/pdf/2004.10657#page=1)); TypeT5 uses the checker's error count as a coherence metric ([Wei et al. 2023, p.1](https://arxiv.org/pdf/2303.09564#page=1)); OptTyper relaxes the logical constraints into a continuous optimization over per-identifier distributions ([Pandi et al. 2020, p.1](https://arxiv.org/pdf/2004.00348#page=1)). In every one of these, uncertainty lives in the proposal and the checker's verdict is treated as certain; none models the probability that a partial program is well typed as a quantity. The only place a checker enters as a likelihood inside inference is the SMC line of section 2.3, where a hard constraint is a potential and a particle violating it gets weight zero. This is an open seam as of 2026-10-09, and it is the seam disp's Open verdict sits in: soft typing is the limit where the checker never refutes, gradual typing is soft typing with programmer-controlled precision, and a budgeted check is soft typing where the inserted guard can be paid for later with more budget instead of at run time.

### 4.4 Typed holes carry the expected type into a generator and never block it

Hazelnut's sensibility theorem "establishes that every edit state is well-typed after cursor erasure" by inserting empty and non-empty holes ([Omar et al. 2017, p.3](https://arxiv.org/pdf/1607.04180#page=3)); Hazel evaluates around holes, yielding "indeterminate" results, and "when the programmer performs an edit that fills an empty expression hole or that replaces a non-empty hole with a type-correct expression, evaluation can resume from the previous evaluation state. We call this operation fill-and-resume" ([Omar et al. 2019, p.3](https://arxiv.org/pdf/1805.00155#page=3)). The marked lambda calculus makes error localization total, "a total procedure for marking arbitrary unmarked expressions", mechanized in Agda and bidirectional so that "localization decisions are systematically predictable based on a local flow of typing information" ([Zhao et al. 2024, p.1](https://hazel.org/papers/marking-popl24.pdf#page=1)); tylr pushes totality down to syntax, completing input "with additional obligations such that it can be parsed into a well-formed term, with success guaranteed over all inputs" ([Moon et al. 2025, p.1](https://arxiv.org/pdf/2508.16848#page=1)). Together these give a generator a checker that never gets stuck: an ill-typed partial program is marked, not rejected, and can still be run for partial evidence; fill-and-resume is the incremental re-check a hole-by-hole generator needs; and indeterminate is an existing formal status for "evaluation could not proceed", though its cause is holes rather than budget. The 2024 LLM integration routes the hole's context into the prompt: the language server collects "types based on the expected type (C) and selecting type-relevant headers from the context (D)" and a static error-correction pass feeds localized errors back ([Blinn et al. 2024, pp.3–4](https://arxiv.org/pdf/2409.00921#page=1)), with the ablation of section 3.6 showing the expected type as the highest-value constraint, since without such context the model "will hallucinate plausible-but-incorrect definitions" ([p.3](https://arxiv.org/pdf/2409.00921#page=3)). The older roots are sketching, where "a partial program, a sketch that expresses the high-level structure of an implementation but leaves holes in place of the low-level details" is solved by counterexample-guided inductive synthesis ([Solar-Lezama 2008, p.4](https://people.csail.mit.edu/asolar/papers/thesis.pdf#page=4)), justified by "an important empirical hypothesis" that a handful of inputs pins down the program ([p.24](https://people.csail.mit.edu/asolar/papers/thesis.pdf#page=24)).

### 4.5 Bidirectional and co-contextual checking are the left-to-right engine

Bidirectional typing's checking mode is the mechanism by which an expected type flows into a subterm before the subterm exists, and it "support[s] features for which inference is undecidable" ([Dunfield & Krishnaswami 2021, p.1](https://arxiv.org/pdf/1908.05839#page=1)); mode-correctness is the guarantee that the checker never needs to search: "whenever we synthesize a type, the type should come from known information—rather than, say, enumerating all possible types" ([p.4](https://arxiv.org/pdf/1908.05839#page=4)). Local type inference recovers annotations "using only information from adjacent nodes in the syntax tree, without long-distance constraints such as unification variables" ([Pierce & Turner 2000, p.1](https://www.cis.upenn.edu/~bcpierce/papers/lti-toplas.pdf#page=1)), which is what makes per-hole checking independent of the unwritten rest of the program. Co-contextual typing inverts the context: rules "only take an expression as input and produce a type and a set of context requirements", so independent subterms check bottom-up and merge ([Erdweg et al. 2015, p.1](https://www.informatik.uni-marburg.de/~seba/publications/cocontextual-type-checking.pdf#page=1)); the Featherweight Java extension proves "the equivalence of FJ's type system and our co-contextual formulation" ([Kuci et al. 2017, p.1](https://arxiv.org/pdf/1705.05828#page=1)), which is the "cheaper checker agrees with the reference" theorem instantiated. Requirements-as-output is precisely the shape of a verdict about a prefix: constraints on what the suffix must provide. Incremental checkers derived by compiling inference rules to Datalog report "multiple orders of magnitude speedups" on some change kinds and slowdowns on others ([Pacak et al. 2020, p.1](https://www.pl.informatik.uni-mainz.de/files/2020/10/incremental-typing-foundations.pdf#page=1)); scope-graph-based Statix reaches "speedups up to 147x on synthetic benchmarks, and up to 21x on real-world projects, with initial overheads below 10%" ([Zwaan et al. 2022, p.2](https://pure.tudelft.nl/ws/portalfiles/portal/142378366/3563303.pdf#page=2)); Hazel's 2025 incremental bidirectional checker updates type information "at a computational cost proportional to the number of potentially affected locations" ([Porter et al. 2025, p.1](https://arxiv.org/pdf/2504.08946#page=1)) and shows "one or more orders of magnitude of speedup" with cost no longer growing in program size ([p.21](https://arxiv.org/pdf/2504.08946#page=21)). A prefix checker for disp should emit both directions: what is known flows down into the hole (the expected type), what is owed flows up and right (requirements on the suffix). The token-level decoders of section 2.2 are two-valued at the implementation level, mask or not, but three-valued semantically, refuted, not yet refuted, proven only at termination; making the "not yet" explicit with a budget is the gap disp targets.

### 4.6 Three-valued verdicts, and the soundness relation that makes "agrees" precise

disp's three outcomes line up one-to-one with existing theory, and the information order on them is Kleene's. In abstract interpretation "Kleene's logic has a third truth value that signifies 'unknown,' which is useful for shape analysis because we only have partial information about the actual stores" ([Sagiv et al. 2002, p.3](https://www.cs.tau.ac.il/~msagiv/toplas02.pdf#page=3)), and an Embedding Theorem relates the 3-valued world to the 2-valued one so "the meaning of a formula in the 'blurred' (3-valued) world is compatible with the formula's meaning in the original (2-valued) world" ([p.7](https://www.cs.tau.ac.il/~msagiv/toplas02.pdf#page=7)). In model checking of incomplete models "The third truth value ⊥ means 'unknown whether true or false'" with a completeness preorder ([Bruns & Godefroid 1999, p.1](https://patricegodefroid.github.io/public_psfiles/cav99.pdf#page=1)). In runtime verification, LTL3 gives "a three-valued semantics (with truth values true, false, inconclusive)" to finite prefixes, anchored to the infinite-trace semantics (true iff every extension satisfies, false iff none does), with monitors that decide "as early as possible" ([Bauer et al. 2011, p.1](https://cs.uwaterloo.ca/~bbonakda/teaching/CS745/papers/RV.pdf#page=1)); this is the cleanest existing theory of a prefix verdict that must agree with a reference semantics, and "as early as possible" is the budget-efficiency criterion. Bounded model checking considers "counterexamples of a particular length k" ([Biere et al. 1999, p.5](http://www.cs.cmu.edu/~emc/15-820A/reading/biere99symbolic.pdf#page=5)), and the completeness threshold is the theory of when a bounded negative upgrades to a proof: "there exists a number CT (the Completeness Threshold) such that if there is no counterexample to φ in M of length CT or less, then M ⊨ φ" ([Clarke et al. 2004, p.1](http://www.kroening.com/papers/vmcai2004.pdf#page=1)), computing which is as hard as model checking, so it exists only for finite fragments. SMT-LIB standardizes the don't-know with a reason: check-sat may return "an unknown response that the search was inconclusive—because of resource limits, solver incompleteness, or other reasons" ([SMT-LIB 2.6, p.65](https://smt-lib.org/papers/smt-lib-reference-v2.6-r2021-05-12.pdf#page=65)) with a reason-unknown value whose grammar is "memout | incomplete | ⟨s_expr⟩" ([p.48](https://smt-lib.org/papers/smt-lib-reference-v2.6-r2021-05-12.pdf#page=48)); the verdict library's open_on reason is this. Refinement types buy decidability the other way, by restricting what a type may say: "Refinements are predicates drawn from decidable logics" ([Jhala & Vazou 2020, p.5](https://arxiv.org/pdf/2010.07763#page=5)), with subtyping reduced to implication checks over base types ([Rondon et al. 2008, p.1](https://ranjitjhala.github.io/static/liquid_types.pdf#page=1)), and refinement reflection notes that axioms "render VC checking undecidable" and can "lead to infinite 'matching loops'", so it unfolds definitions in a bounded, terminating way instead ([Vazou et al. 2018, p.8](https://arxiv.org/pdf/1711.03842#page=8)), a published cousin of "proven within budget". disp keeps types unrestricted and bounds the checker instead.

The semantic meaning of a budget-bounded acceptance already exists as a standard model construction. Step-indexed types are "type judgements that are indexed: v :_k τ intuitively means that, in any computation running for no more than k steps, the value v behaves as if it were an element of the type τ" ([Appel & McAllester 2001, p.3](https://www.cs.princeton.edu/~appel/papers/indexed.pdf#page=3)), downward closed in k, so a finite k gives a sound under-approximation of the type that converges to it as k grows; Ahmed's relational version, "in any computation running for no more than k steps, v approximates v′ at the type τ" ([Ahmed 2006, p.4](https://www.ccs.neu.edu/home/amal/papers/lr-recquant.pdf#page=4)), is what an optimizer replacing one program by another under a type needs. "Proven" is membership for all k, "no counterexample within budget k" is v :_k τ, and refutation at any k is definitive. The general "cheaper checker agrees with canonical" theorem is abstract interpretation's soundness relation: "safety, correctness or soundness is established by proving that a soundness relation σ satisfies ∀p ∈ L : σ(S⟦p⟧, S♯⟦p⟧)" ([Cousot 1996, p.1](https://cs.nyu.edu/~pmc309/publications.www/Cousot-ACM-Computing-Surveys-v28-n2-p324-328-1996.pdf#page=1)); the practice of giving σ up has a name, soundiness, under which "virtually all published whole-program analyses are unsound and omit conservative handling of common language features" ([soundiness.org](http://soundiness.org/#Introduction)), and a checker that returns Open instead of silently assuming is the principled alternative. The verdict library's agrees contract (Proved needs the enumerated run to pass, Refuted needs it to fail, Open is consistent with either) is the LTL3 anchoring and Cousot's σ written as a disp function.

## 5. Compute-parameterized and modular type theories: cost in judgments, fuel in semantics, the checker's own budget almost nowhere

### 5.1 Cost-aware frameworks prove cost about programs and never budget the checker

The cost-aware logical framework calf (POPL 2022) does not put a budget in the typing judgment; it puts cost into the term language as an effect and separates behaviour from cost by a modal phase distinction: "the cost structure of programs motivates a phase distinction between intension and extension... a synthetic account of cost structure as a computational effect in which cost-aware programs enjoy an internal noninterference property: input/output behavior cannot depend on cost" ([Niu et al. 2021, p.1](https://arxiv.org/pdf/2107.04663#page=1)); the reference implementation is an Agda library ([agda-calf](https://github.com/jonsterling/agda-calf#calf-a-cost-aware-logical-framework)). decalf (POPL 2024) drops the separable cost effect: "rather than rely on a separable notion of cost, here a cost bound is simply another program. Formally, every type is equipped with an intrinsic preorder, allowing effectful programs to be compared for cost inequality", an ordering that "restricts in the behavioral phase to extensional equality" ([Grodin et al. 2023, p.1](https://arxiv.org/pdf/2307.05938#page=1)). Follow-ups relate denotational to computational cost for a cost-aware PCF ([Niu et al. 2024, p.1](https://arxiv.org/pdf/2404.00212#page=1)) and prove calf's canonicity ([Li & Harper 2025, p.1](https://arxiv.org/pdf/2504.12464#page=1)). Two things transfer and one does not. The noninterference theorem is exactly the property disp wants between a fast checker and the canonical stream: the accept-or-refute answer must be invariant under how many steps were spent getting it. decalf's "a cost bound is simply another program" is the same move as disp's "a type is a program", so an optimizer can search over cost bounds as it searches over programs, which is what the cost coeffect in the optimizer design document assumes. What is absent is any third answer: these judgments are two-valued, and "the checker ran out of fuel" has no semantics here; no calf or decalf paper treats the type checker's own running time.

### 5.2 Graded types make the resource algebra the parameter

Graded systems annotate variables with elements of a semiring and let the rules add and multiply them; the semiring is the parameter. Quantitative Type Theory "records usage information for each variable in a judgement" and gives it "a realizability semantics using a variant of Linear Combinatory Algebras" ([Atkey 2018, p.1](https://bentnib.org/quantitative-type-theory.pdf#page=1)), with McBride's insight that the 0 of the semiring represents "information that is erased at runtime, but is still available for use in types", a syntactic intension/extension split complementary to calf's modal one. Granule generalizes to "a family of modalities whose indices are drawn from an arbitrary semiring, enabling various properties to be tracked by a single system" ([Orchard et al. 2019, p.1](https://www.cs.kent.ac.uk/people/staff/dao7/publ/granule-icfp19.pdf#page=1)), the project's stated aim being to capture "how a program computes not just what it computes" ([granule-project.github.io](https://granule-project.github.io/)). Graded modal dependent type theory reports "an application of grading to optimising the type checking procedure itself" by skipping substitution into unused positions ([Moon et al. 2021, p.1](https://arxiv.org/pdf/2010.13163#page=1)), the one place in this cluster where grades make the checker cheaper, justified by the typing derivation rather than a separate agreement proof. Resource Aware ML takes the opposite style, no grades in source types, "Bound inference is fully automatic and reduced to a linear optimization problem" ([Hoffmann et al. 2016, p.1](https://arxiv.org/pdf/1611.00692#page=1)). The semiring-as-parameter design is the closest existing analogue of a swappable resource discipline: change what the checker tracks by changing an algebra, not the rules. But in all of these the grade is computed statically by a solver that is itself unbounded and never represents steps the checker actually spent; a disp type that inspects a value's structure would be the "used arbitrarily often" grade in type position, which the zero grade cannot describe.

### 5.3 Fuel, delay and step indices give the budget its semantics

Three budget devices exist and approximate differently. Step-indexed models (section 4.6) make "behaves like τ for k steps" a membership relation that is downward closed: "if e :k τ and 0 ≤ j ≤ k then e :j τ" ([Appel & McAllester 2000, p.1](https://www.cs.princeton.edu/techreports/2000/629.pdf#page=1)). Guarded dependent type theory internalizes the index as a later modality "used to ensure the productivity of recursive definitions in a modular, type based, way", with clock quantifiers to recover coinductive types ([Bizjak et al. 2016, p.1](https://arxiv.org/pdf/1601.01586#page=1)). Partiality monads move general recursion into a total language: Capretta's delay monad treats "Partiality as a monad" and contrasts it with restricting a function to its domain of convergence ([Capretta 2005, p.1](https://lmcs.episciences.org/2265/pdf#page=1)); McBride shows that "general recursive definitions can be represented in the free monad which supports the 'effect' of making a recursive call, without saying how these calls should be executed. Diverse semantics can be given within a total framework by suitable monad morphisms" ([McBride, p.1](https://personal.cis.strath.ac.uk/conor.mcbride/TotallyFree.pdf#page=1)). That last sentence is the theoretical licence for the gradual stream checker's architecture: a type-as-program that may not terminate is a total function into a delay type, the budget is how many later-steps one peels, and fast checkers are different interpreters of the same canonical stream, related by monad morphisms rather than by re-implementation. Practice has two other responses. Agda's NON_TERMINATING pragma marks definitions that "do not reduce during type checking. Though, they do reduce at run-time" ([Agda docs](https://agda.readthedocs.io/en/latest/language/termination-checking.html#non-terminating-pragma)), and Trellys/Zombie splits the language into "a logic that guarantees total correctness, and a call-by-value programming language that guarantees type safety but not termination" ([Casinghino et al. 2014, p.1](https://www.engineering.upenn.edu/~sweirich/papers/popl14-trellys.pdf#page=1)), both "do not unfold it" strategies that preserve decidability by refusing to run possibly-looping code at check time. disp's design is instead "run it, but count", and the only earlier dependently typed checker that did the same is Cayenne (1998): "type checking of Cayenne is undecidable. While this may appear to be a steep price to pay, it seems to work well in practice" ([Augustsson 1998, p.1](https://www.cs.tufts.edu/~nr/cs257/archive/lennart-augustsson/cayenne.pdf#page=1)), and in its section 4.4, "the implemented type checker has an upper bound on the number of reduction steps that it may perform. If this limit is exceeded the type checker will report this", a report that "Most often... is the result of a type error, but sometimes the type expression is just too complicated and the number of reduction steps must be increased" ([Cayenne, §4.4](https://www.cs.tufts.edu/~nr/cs257/archive/lennart-augustsson/cayenne.pdf)). Cayenne treated the third outcome as an error with a user-tunable flag; GDTL (section 4.2) instead made compile-time evaluation approximate but total. disp's Open with a reason is Cayenne's report made a first-class value with the SMT-LIB discipline of saying why.

### 5.4 Checking by computation, and the three ways to say "the fast checker agrees"

Proof by reflection already is "a type is a program that answers yes or no": write a boolean decision procedure, prove once that its true answer implies the proposition, then run it per instance; the small-scale reflection methodology formalizes finite objects this way in Rocq ([Gonthier & Mahboubi 2010](https://jfr.unibo.it/article/view/1979)). The trade is where the running happens, and the proof assistants have made that a trust ledger. Lean's kernel-only route "only use[s] the three standard axioms (propext, Quot.sound, and Classical.choice)"; its compiled route, native_decide, "should be used with care because it adds the entire lean compiler to the trusted part, and a new axiom will show up in #print axioms for theorems using this method", while being "significantly more efficient" ([Lean reference, native_decide](https://lean-lang.org/doc/reference/latest/Tactic-Proofs/Tactic-Reference/#native_decide)); the marker is per use and auditable: "The native_decide tactic creates a bespoke axiom for each invocation. This allows each axiom to be audited for the precise statement that it proves." ([Lean reference, Axioms](https://lean-lang.org/doc/reference/latest/Axioms/#standard-axioms)). Rocq's vm_compute and native_compute, the latter "typically two to five times faster", each "add a single explicit cast to the proof term to tell the kernel which reduction engine to use" ([Rocq manual](https://rocq-prover.org/doc/master/refman/proofs/writing-proofs/equality.html#applyingconversionrules)), and the original compiled evaluator came with the reason a proof is required: "Such a mechanically-checked correctness proof is required to ensure that we do not compromise the logical consistency of the Coq system by plugging a buggy evaluator in it." ([Grégoire & Leroy 2002, p.1](https://xavierleroy.org/publi/strong-reduction.pdf#page=1)). MetaRocq's verified checker states precisely what one must assume to drop the budget: a "fuel-free and verified reduction machine, conversion checker and type checker for PCUIC. This relies on a postulate of strong normalization of the reduction relation of PCUIC on well-typed terms" ([MetaRocq](https://github.com/MetaRocq/metarocq)). Certifying algorithms are the third frame: "an algorithm that produces, with each output, a certificate or witness (easy-to-verify proof) that the particular output has not been compromised by a bug" ([McConnell et al. 2011, p.1](https://people.mpi-inf.mpg.de/~mehlhorn/ftp/CertifyingAlgorithms.pdf#page=1)). So "cheap checker agrees with canonical checker" has three existing formalizations: a verified evaluator, where agreement is a theorem; an explicit trust axiom per use, where agreement is assumed and recorded so it can be audited or forbidden; and a certifying witness, where the fast checker emits something the canonical one verifies cheaply. For disp, the faster implementations in .opt.disp files that overwrite canonical definitions are native_decide-class artifacts: each needs either an agrees-style contract checked against the stream, a recorded trust marker, or a certificate (a refuting witness is one already; a Proved by shortcut is the one that needs the ledger). The only way to be fuel-free is MetaRocq's postulate, which disp does not have for arbitrary tree-calculus recognizers.

### 5.5 Refutation-first and anytime: report the bound with the negative result, never upgrade silently

Bounded and random testing state their result as "no counterexample up to the bound", never as "true". QuickCheck tests properties "on random input" ([Claessen & Hughes 2000, p.1](https://www.cs.tufts.edu/~nr/cs257/archive/john-hughes/quick.pdf#page=1)); SmallCheck tests "for all values up to some limiting depth, progressively increasing this limit" ([Runciman et al. 2008](https://research.chalmers.se/en/publication/111867#publication-abstract)), and its maintainers now call it "largely obsolete" in favour of generators with shrinking ([Hackage, 2023 note](https://hackage.haskell.org/package/smallcheck#description)); the small-scope hypothesis was tested for data structures with the finding that "Exhaustive testing within small scope can generate mutation-adequate test suites" ([Marinov et al. 2003, p.1](https://www.cs.columbia.edu/~andoni/papers/TR921.pdf#page=1)), and Alloy analyses within a user-chosen scope ([Jackson 2002, p.6](https://groups.csail.mit.edu/sdg/pubs/2002/alloy-journal.pdf#page=6)). Bounded model checking makes "the bound... the maximal length of a counterexample", reduces to SAT, and "produces counterexamples of minimal length" ([Biere et al. 1999, p.3](http://www.cs.cmu.edu/~emc/15-820A/reading/biere99symbolic.pdf#page=3)); k-induction turns bounded search into proof by combining it with an inductive step ([Sheeran et al. 2000, p.1](https://www.di.ens.fr/~pouzet/cours/mpri/sheeran-FMCAD00.pdf#page=1)). Anytime algorithms are the decision-theoretic frame for a checker that can be stopped: they "can be interrupted at any point during computation to return a result whose utility is a function of computation time" ([Dean & Boddy 1988, p.1](https://cdn.aaai.org/AAAI/1988/AAAI88-009.pdf#page=1)), and the control problem of composing several of them, which to run and for how long, is Zilberstein's survey subject ([Zilberstein 1996](https://ojs.aaai.org/aimagazine/index.php/aimagazine/article/view/1232#pkp_content_main)); that is exactly the problem a pipeline of fast shortcuts plus a slow canonical stream faces. The small-scope hypothesis is also the empirical justification for running the cheap refuter first: if most type errors show at tiny inputs, a short budget already carries most of the refutation value, and a minimal counterexample (BMC's) is the best witness to hand a conflict-learning step.

### 5.6 Decidability conditional on the parameter: logical frameworks, multimodal type theory, and the tree calculus

Making the type theory a parameter comes in two families. Logical frameworks make the object theory a signature checked by a fixed small kernel: in LF "each judgement is identified with the type of its proofs... proof checking is reduced to type checking", so "logic-independent tools such as proof editors and proof checkers can be constructed" ([Harper, Honsell & Plotkin 1991](https://www.lfcs.inf.ed.ac.uk/reports/91/ECS-LFCS-91-162/#spacer)); Dedukti's λΠ-calculus modulo theory adds rewrite rules to contexts and uses one framework "to audit formal proofs develop in these systems by checking them in a different, independent, system" toward "a single distributed library of formal proofs expressed in different theories" ([Assaf et al. 2023, p.3](https://arxiv.org/pdf/2311.07185#page=3)); Andromeda 2 "is a proof checker for user-definable dependently-typed theories" where "There is an abstract datatype judgement whose values can only be constructed by a nucleus, a small trusted component", and "Normalization, unification, and other proof development techniques reside" outside it ([andromeda-prover.org](https://www.andromeda-prover.org/)); Bauer, Haselwarter and Lumsdaine define raw, acceptable and well-presented type theories in general and prove "fundamental fitness-for-purpose metatheorems" for the whole class, much of it formalized ([2020, p.1](https://arxiv.org/pdf/2009.05539#page=1)). Parameterized theories prove the metatheory once, conditionally: Multimodal Type Theory "can be instantiated by a mode theory, a strict 2-category describing modes, modalities, and natural transformations", with consistency and canonicity holding "irrespective of the choice of mode theory" ([Gratzer et al. 2020, p.1](https://arxiv.org/pdf/2011.15021#page=1)), and its normalization paper (LMCS, March 2026) gives the shape of theorem disp can hope for: "type checking is decidable when the mode theory is decidable", while noting that flexibility "becomes proportionally more challenging to prove metatheoretic results about" ([Gratzer 2026, p.1](https://arxiv.org/pdf/2301.11842#page=1)). Two-level type theory layers an inner and an outer theory ([Annenkov et al. 2017, p.1](https://arxiv.org/pdf/1705.03307#page=1)); type theory inside type theory defines "directly well typed objects by an inductive definition" with quotient inductive types ([Altenkirch & Kaposi 2016, p.1](https://people.cs.nott.ac.uk/psztxa/publ/tt-in-tt.pdf#page=1)); Cocon supports "type-level computation thereby providing metaprogramming and (small-scale) reflection" with a normalization proof ([Pientka et al. 2019, p.1](https://arxiv.org/pdf/1905.02617#page=1)). The checker-as-program line is MetaRocq (section 5.4) and Lean 4, which "has a relatively small trusted kernel, and the rich API allows users to export their developments to other systems and implement their own reference checkers" ([de Moura & Ullrich 2021, p.1](https://lean-lang.org/papers/lean4.pdf#page=1)); Lean4Lean records the cost of touching the canonical checker for speed: the kernel "was extended with various features for performance reasons like bignum arithmetic, nested inductive types, and primitive projections, and unfortunately some soundness bugs crept in during the process", and "the external checkers" were lost in the port ([Carneiro 2024, p.1](https://arxiv.org/pdf/2403.14064#page=1)).

What is gained is one kernel for many logics, cross-checking in an independent system, one metatheory proof for a family, and a checker that is itself a verified or at least swappable program. What breaks is that consistency and canonicity of the object theory are no longer the framework's business (Andromeda's nucleus guarantees only that derivations follow the user's rules; Dedukti must trust that the rewrite system is confluent and terminating; MTT's decidability is conditional), the trusted core moves (the C++ kernel plus, for native_decide, the compiler; a strong-normalization postulate; a nucleus with normalization outside it), and performance changes to the canonical checker are the historical source of trust failures. Andromeda's split, a tiny nucleus that only constructs judgements with all search and normalization outside, is the closest existing architecture to "the type checker is a program to be optimized and swapped": fast checkers live outside and must produce nucleus-accepted evidence. The MTT shape for disp is "the checker terminates if the type's recognizer terminates".

The substrate matters for whether "type = program" is even coherent. Realizability already takes a type to be a set of untyped realizers from a partial combinatory algebra, with "modest sets" and "assemblies" as the categorical packaging ([Bauer, p.5](https://math.andrej.com/data/c2c.pdf#page=5), [p.6](https://math.andrej.com/data/c2c.pdf#page=6)), and QTT's semantics is a linear variant of exactly this. What disp adds is that the membership test is itself a term of the same calculus, which in Kleene's first model is impossible in general. Jay's tree calculus is "simple because it is based on three equations only; powerful because one program can query the internal structure of another, using a mix of extensional and intensional techniques" ([Jay, p.5](https://raw.githubusercontent.com/barry-jay-personal/tree-calculus/master/tree_book.pdf#page=5)), and the book frames program analyses, "including type systems and evaluation strategies", as reflective programs: "In tree calculus, a program analysis is a reflective program." ([Jay, pp.8–9](https://raw.githubusercontent.com/barry-jay-personal/tree-calculus/master/tree_book.pdf#page=8)). The intensional thesis behind it is that "a modern combinatory calculus, the SF-calculus, can define equality of its closed normal forms", which λ-models cannot ([Jay & Vergara 2014, p.12](https://arxiv.org/pdf/1410.7103#page=12)). Definable equality and self-interpretation are what make a syntactic recognizer expressible for decidable properties and a semi-decidable one (run and see) for the rest. A recognizer over all terms inherits section 1's limits in a specific way: it can inspect structure (intensional, terminating) and it can apply (extensional, possibly non-terminating), and only the second kind of step consumes budget, so a checker should run intensional tests first. Jay's own typed fragment is, as of the fetched draft, a Tait-style simple type system by tagging, flagged by the author as unfinished; there is no published dependent type theory over the tree calculus to compare against.

## 6. RL and formal systems: the verifier fills every slot, the value estimates completability, training amortizes a search

### 6.1 Four slots for one bit

The lineage runs from AI-judge preferences to programmatic rewards. Constitutional AI replaced human harm labels with model critiques where "The only human oversight is provided through a list of rules or principles" ([Bai et al. 2022, p.1](https://arxiv.org/pdf/2212.08073#page=1)); RLAIF "achieves comparable performance to RLHF" with LLM-generated preference labels ([Lee et al. 2023, p.1](https://arxiv.org/pdf/2309.00267#page=1)). Tülu 3 named the next step "Reinforcement Learning with Verifiable Rewards (RLVR)", a stage that "trains the model on verifiable rewards instead of a reward model" ([Lambert et al. 2024, p.1](https://arxiv.org/pdf/2411.15124#page=1)), and DeepSeek-R1 avoided learned judges for reasoning because "neural reward models are susceptible to reward hacking during large-scale reinforcement learning", using a compiler and test cases for code instead ([DeepSeek-AI 2025, p.4](https://arxiv.org/pdf/2501.12948#page=4)). Two 2025 controls complicate the reading of any RLVR gain. Random rewards improved Qwen2.5-Math-7B on MATH-500 "by 21.4% using randomly assigned rewards, nearly matching the 29.1% gained with ground truth rewards", attributed to an optimizer clipping bias amplifying pretrained behaviours, and not transferring to other model families ([Shao et al. 2025, p.1](https://arxiv.org/pdf/2506.10947#page=1)); and at large k the base model's pass@k overtakes the RL-trained model's, so "their reasoning abilities originate from and are bounded by the base model" ([Yue et al. 2025, p.1](https://arxiv.org/pdf/2504.13837#page=1)). A verifier reward behaves less like teaching and more like amortizing a search (section 6.4). A from-scratch program searcher has no pretrained prior for these artifacts to ride on, but the controls, random reward and pass@k versus pass@1, are cheap and worth copying.

In formal domains the proof assistant now occupies all four slots at once. As the online reward: DeepSeek-Prover-V1.5 introduced "reinforcement learning from proof assistant feedback (RLPAF)" with Lean as the reward ([Xin et al. 2024, p.1](https://arxiv.org/pdf/2408.08152#page=1)); V2 uses binary correctness as "the primary form of reward supervision" with an early structural consistency term ([Ren et al. 2025, p.10](https://arxiv.org/pdf/2504.21801#page=10)); Seed-Prover states the premise in one sentence, "Dedicated domain-specific languages like Lean provide clear supervision via formal verification of proofs, enabling effective training through reinforcement learning" ([Chen et al. 2025, p.1](https://arxiv.org/pdf/2507.23726#page=1)); Leanabell-V2 feeds verifier messages back into the chain of thought ([Ji et al. 2025, p.1](https://arxiv.org/pdf/2507.08649#page=1)); Re:Form uses the Dafny verifier as the RL signal for verified programs, not just proofs, "RL with regularization further improves performance" over SFT ([Yan et al. 2025, p.1](https://arxiv.org/pdf/2507.16331#page=1)), the closest existing setting to disp's objective; Kim and Yun parse proofs into tactics, use Lean elaboration to mark locally sound steps and the first failing one, and find "tactic-level supervision outperforms outcome-only baselines" in most settings ([Kim & Yun 2026, p.1](https://arxiv.org/pdf/2606.20068#page=1)); and Cai et al. model an imperfect verifier as "a stochastic reward channel with asymmetric noise rates" and derive unbiased policy-gradient corrections ([Cai et al. 2025, p.1](https://arxiv.org/pdf/2510.00915#page=1)), the formal bridge between an exact checker and a leaky one. As the offline filter that manufactures data: STaR keeps only rationales that reach the right answer ([Zelikman et al. 2022, p.1](https://arxiv.org/pdf/2203.14465#page=1)); ReST-EM makes the EM reading explicit, "(1) generate samples from the model and filter them using binary feedback, (2) fine-tune the model on these samples, and (3) repeat" ([Singh et al. 2023, p.1](https://arxiv.org/pdf/2312.06585#page=1)); DeepSeek-Prover built 8 million verified Lean statements ([Xin et al. 2024, p.1](https://arxiv.org/pdf/2405.14333#page=1)) and Goedel-Prover 1.64 million ([Lin et al. 2025, p.1](https://arxiv.org/pdf/2502.07640#page=1)), with Lean-STaR letting informal thoughts ride along unverified beside the verified formal part ([Lin et al. 2024, p.1](https://arxiv.org/pdf/2407.10040#page=1)). As the curriculum: expert iteration "is capable of finding and solving a curriculum of increasingly difficult problems, without the need for associated ground-truth proofs" ([Polu et al. 2022, p.1](https://arxiv.org/pdf/2202.01344#page=1)), the earliest clear statement; Goedel-Prover-V2 adds "scaffolded data synthesis" of "synthetic tasks of increasing difficulty" and "Verifier-guided self-correction" in one pipeline ([Lin et al. 2025, p.1](https://arxiv.org/pdf/2508.03613#page=1)). As the labeller: BFS-Prover applies "Direct Preference Optimization (DPO) applied to state-tactic pairs automatically annotated with compiler error feedback" ([Xin et al. 2025, p.1](https://arxiv.org/pdf/2502.03438#page=1)), and JURY-RL has "votes from model rollouts propose a candidate answer, and a formal verifier determines whether that candidate can receive positive reward" ([Chen et al. 2026, p.1](https://arxiv.org/pdf/2604.25419#page=1)), the clean division of soft proposes, hard disposes. The four slots are one binary signal consumed at different times: online, offline, by difficulty statistics over a batch, and by pairwise comparison. No 2025–2026 paper was found that uses a general-purpose language's type checker as an RL reward at scale; the formal-reward literature is Lean, Dafny, Verus and unit tests. disp's cost multiplier, unlike its checker, is a learned or heuristic proxy and inherits every reward-model hazard.

### 6.2 Process reward models are policy-weighted completability, a lower-biased soft oracle

Human step labels came first: "process supervision significantly outperforms outcome supervision" on MATH with 800k human step labels ([Lightman et al. 2023, p.1](https://arxiv.org/pdf/2305.20050#page=1)); Math-Shepherd replaced them with Monte Carlo completions from each prefix ([Wang et al. 2023, p.1](https://arxiv.org/pdf/2312.08935#page=1)). Then came the precise re-reading. Setlur et al. observe that prior PRMs score a prefix by "computing the expected future accuracy of multiple completions sampled from" the base policy, which is the Q-function, and that the useful dense signal is the advantage, "Crucially, this progress should be measured under a prover policy distinct from the base policy", since with the prover equal to the base policy the update collapses to outcome rewards ([Setlur et al. 2024, p.1](https://arxiv.org/pdf/2410.08146#page=1)). The Qwen team found that Monte Carlo step labels "typically yield[] inferior performance and generalization compared to LLM-as-a-judge and human annotation methods" because the estimate "attempts to evaluate deterministic current-step correctness based on potential future outcomes" and depends on the completion policy; their consensus filter kept "approximately 40% of the data" ([Zhang et al. 2025, p.1](https://arxiv.org/pdf/2501.07301#page=1)). Process Q-value models state the MDP reading and train rankings instead of per-step classifications ([Li et al. 2024, p.1](https://arxiv.org/pdf/2410.11287#page=1)). Implicit PRMs come "at no additional cost, by simply training an ORM on the cheaper response-level labels" via a log-likelihood-ratio parameterization ([Yuan et al. 2024, p.1](https://arxiv.org/pdf/2412.01981#page=1)), but that ratio "is constrained only as a sequence-level aggregate during training", so "This train-inference mismatch leaves local credits weakly identified" ([Gao et al. 2026, p.1](https://arxiv.org/pdf/2604.13197#page=1)): a soft prefix value learned only from end-of-sequence acceptance is under-determined exactly where search needs it. Nikulkov shows a well-trained reward model's output at any token should be the "conditional expectation of the final reward given the response so far" and that a temporal-difference smoothness loss recovers Bellman consistency ([Nikulkov 2026, p.1](https://arxiv.org/pdf/2604.22981#page=1)); Sullivan et al. prove GRPO with an outcome reward is "equivalent to a PRM-aware RL objective equipped with a non-trivial, Monte-Carlo-based PRM" ([Sullivan et al. 2025, p.1](https://arxiv.org/pdf/2509.21154#page=1)), so a binary verifier at the end plus group sampling already implies step-level Monte Carlo credit, with its failure modes. Generative verifiers move verifier compute onto the generation scaling axis ([Zhang et al. 2024, p.1](https://arxiv.org/pdf/2408.15240#page=1); [Khalifa et al. 2025, p.1](https://arxiv.org/pdf/2504.16828#page=1)). In proof search the learned critic is the same object: HyperTree Proof Search found that setting internal nodes to zero "is too pessimistic" and that the best critic target was the search's own action-value estimate ([Lample et al. 2022, p.14](https://arxiv.org/pdf/2205.11491#page=14)); MPS-Prover's critic predicts a tree distance where "the smaller the predicted distance, the closer the node is to a successful proof" ([Liang et al. 2025, p.4](https://arxiv.org/pdf/2505.10962#page=4)), the natural shape for a cost-to-go under a "cost times checker" objective; AlphaProof is the largest value-guided search against an exact Lean oracle to date ([Hubert et al. 2025](https://www.nature.com/articles/s41586-025-09833-y#ref-link-section-d157923345e754)).

The precise reading, which the notes derive and which nothing in the literature contradicts: let A(y) be the hard oracle on complete programs and C(x) = 1 iff some completion of prefix x has A(y) = 1. Every Monte Carlo PRM, implicit PRM, temporally coherent outcome model and SMC twist estimates Q under the policy, the policy-weighted probability that a completion sampled from the policy is accepted. Q > 0 implies C = 1, but Q = 0 does not imply C = 0, since the policy may simply never find the completion. The PRM is a lower-biased soft estimate of completability whose bias is exactly the policy's search failure, which is why Monte Carlo labels were unreliable for Qwen and why Setlur needs a stronger prover to define progress. Human step labels estimate a different predicate, local step validity, which for a typed language is what an incremental checker returns (Kim and Yun's per-tactic elaboration). The useful decomposition for disp is a hard incremental checker for local validity, a soft value for completability, and the advantage as the shaped reward; and HTPS's "too pessimistic" is the proof-search statement that a budget returning Open must not be read as a zero training target. No paper bounds the gap between the Monte Carlo completability estimate and the true oracle; the policy dependence is documented empirically only.

### 6.3 Test-time scaling: an exact verifier turns coverage into accuracy; a learned one caps it

With an exact verifier, repeated sampling converts coverage into accuracy and coverage "scales with the number of samples over four orders of magnitude" with a relationship that "is often log-linear"; "In domains like coding and formal proofs, where answers can be automatically verified, these increases in coverage directly translate into improved performance", whereas majority voting and reward models "plateau beyond several hundred samples" ([Brown et al. 2024, p.1](https://arxiv.org/pdf/2407.21787#page=1)). With a learned verifier the curve has a ceiling no compute removes: resampling "is fundamentally limited when verifiers are imperfect and have a non-zero probability of producing false positives", "there is a strong correlation between the model's single-sample accuracy and its false positive rate", and "optimal sampling attempts are often fewer than 10" once false positives carry a cost ([Stroebl et al. 2024, p.1](https://arxiv.org/pdf/2411.17501#page=1)); optimizing a proxy reward "too much can hinder ground truth performance, in accordance with Goodhart's law", with a functional form that depends on whether the optimizer is RL or best-of-n ([Gao et al. 2022, p.1](https://arxiv.org/pdf/2210.10760#page=1)); and "a significant performance gap remains between" learned judges and "oracle verifiers (verifiers with perfect accuracy)", which weak-verifier ensembles narrow without closing ([Saad-Falcon et al. 2025, p.1](https://arxiv.org/pdf/2506.18203#page=1)). Dense verifiers change the allocation rather than the ceiling: a compute-optimal allocation across beam, lookahead and best-of-N improves efficiency "by more than 4x compared to a best-of-N baseline", with effectiveness that "critically varies depending on the difficulty of the prompt" ([Snell et al. 2024, p.1](https://arxiv.org/pdf/2408.03314#page=1)). For disp the type checker is exact relative to the type, so the checker axis is plateau-free and bounded only by the generator's support; the residual false-positive channel is statement-versus-intent (section 6.7), and the cost score is a learned or heuristic proxy with a Gao-style turn-over on its own axis. Allocating a step budget per candidate is Snell's problem with the PRM replaced by a partial checker run.

### 6.4 RL as inference: the verifier is a likelihood, the mask a local approximation, training an amortization

KL-regularized RL's optimum is the prior reweighted by exp(reward/β) and normalized, a Bayesian posterior. Levine's tutorial develops control as inference with an optimality variable whose likelihood is exp(reward) ([Levine 2018, p.1](https://arxiv.org/pdf/1805.00909#page=1)); Korbak, Perez and Buckley state it for language models: "KL-regularised RL is equivalent to variational inference: approximating a Bayesian posterior which specifies how to update a prior LM to conform with evidence provided by the reward function", and unregularized RL "leads to distribution collapse" ([Korbak et al. 2022, p.1](https://arxiv.org/pdf/2205.11275#page=1)); Fan (September 2026, single-author preprint) generalizes every post-training method to "construct a (generalized) Bayes or Gibbs posterior from a reference model and a utility signal... then approximate it by a forward-KL projection onto a parametric family", reading reasoning models as "combining test-time Bayesian search with training-time amortization" ([Fan 2026, p.1](https://arxiv.org/pdf/2609.05111#page=1)). Twisted SMC makes the prefix-level object explicit: tasks defined by a terminal reward or potential are "sampling from an unnormalized target distribution", "learned twist functions... estimate the expected future value of the potential at each timestep", and the optimal twists "correspond to the conditional likelihood of" the terminal observation given the prefix ([Zhao et al. 2024, p.1](https://arxiv.org/pdf/2404.17546#page=1)); bidirectional SMC bounds then estimate the KL between the sampler and the target, which is how one measures how far a learned sampler is from the constrained posterior. Amortization is defined by GFlowNet fine-tuning: constrained generation requires "sampling from intractable posterior distributions", addressed "by using amortized Bayesian inference" so the fine-tuned policy samples the posterior in one pass instead of N candidates plus a verifier ([Hu et al. 2023, p.1](https://arxiv.org/pdf/2310.04363#page=1)); Deleu et al. show the MaxEnt-RL marginal "may be biased in cases where there are multiple ways to generate the same object" and that flow-matching objectives equal MaxEnt RL "with a corrected reward" ([Deleu et al. 2024, p.1](https://arxiv.org/pdf/2402.10309#page=1)), which matters because programs and proofs are multi-path objects; the only GFlowNet study against a proof checker is explicitly preliminary ([Ho et al. 2024, p.1](https://arxiv.org/pdf/2410.13224#page=1)).

Put together: take a verifier A(y) ∈ {0,1}. The constrained target is p(y | A = 1) ∝ p₀(y)·A(y), Korbak's posterior with reward log A(y) (zero or minus infinity), or the β → 0 limit with reward in {0,1} (this identification is the notes' inference; no 2025–2026 paper states it for verifier rewards). In Loula's terms A is a potential; in Zhao's the prefix likelihood is the twist ψ(x) = Pr[A = 1 | prefix x] under the base model, which is the completability estimate of section 6.2 and the expected future grammaticality of section 2.3. A token mask is a local potential, exact only when it equals the expected-future-acceptance ratio; otherwise it distorts the posterior. Partial runs of a step-budgeted checker form a monotone family of cheap potentials: "rejected within k steps" is exact and can be a mask; "not yet accepted within k steps" is uninformative and must be a weight, never a mask. What RL buys is that rejection sampling or SMC against the exact checker costs N candidates and N checker runs per accepted program, and a policy trained toward the posterior moves that cost to training; Yue et al.'s pass@k result is the empirical face of this. No paper applies GFlowNet or twisted-SMC fine-tuning to program synthesis against a type checker.

### 6.5 Constrained rollouts inside training, and the gradient term nobody has written down

Only one 2024–2026 paper trains with grammar-constrained rollouts, and it deliberately scores them with the unconstrained model: GrammarRL defines the constrained policy by masking and renormalizing, generates constrained rollouts, computes the probabilities used for rewards and losses with the unconstrained model (a design choice stated at its Eq. 3; the surrounding numbers were not re-verified), and notes that rewards "cannot be optimized by backpropagating through the decoding decisions" ([GrammarRL 2026, p.5](https://arxiv.org/pdf/2609.39869#page=5)). The question this leaves open is simple to state. With unconstrained policy π and mask m, the sampled policy is π_m(a | x) = π(a | x)·m(a | x) / Z(x), and its score function is ∇log π_m = ∇log π − ∇log Z. Training on masked samples with ∇log π drops the −∇log Z term, so the update is a REINFORCE step for the unconstrained policy evaluated off-policy under π_m without importance correction; the dropped term is the one that would teach π to put mass inside the mask on its own. This is the notes' derivation; no paper states it, and GrammarRL does not discuss the mismatch. The consequences follow: either compute log-probabilities under π_m and deploy with the mask, or train π with the mask as a terminal 0/1 potential and importance weights (Loula), or correct the mask toward expected future acceptance (Park). For a budgeted checker, only the exact-rejection half of the verdict can be a mask in either regime. The step-level formal signals actually used in training are compiler feedback on partial programs with unexecuted segments masked out of the loss, because "optimizing LLMs by using these unexecuted code snippets is ineffective" ([Dou et al. 2024, p.1](https://arxiv.org/pdf/2402.01391#page=1)); execution feedback as an observation across turns ([Gehring et al. 2024, p.1](https://arxiv.org/pdf/2410.02089#page=1)); a staged pipeline in which "runtime is a fragile reward" meaningful only after correctness, so failed programs are ordered by how far they progress through extraction, compilation, execution and oracle checking before any runtime score applies ([Jing et al. 2026, p.1](https://arxiv.org/pdf/2607.27271#page=1)), which is exactly the shape of "checker times cost"; and per-tactic Lean elaboration (Kim and Yun). The one system with constrained, type-directed generation inside a self-improvement loop is Minimo, which "uses constrained decoding and type-directed synthesis to sample valid conjectures" and "guarantees well-formed conjectures by construction, even as we start with a randomly initialized model" ([Poesia et al. 2024, p.1](https://arxiv.org/pdf/2407.00695#page=1)), the closest precedent to a dependent type theory's rules as a hard mask inside self-play. No one found trains with a type checker at every token; the practical reasons are Loula's per-token cost and StepCoder's observation that partial programs fail for reasons unrelated to the eventual program, and disp's cheap incremental checks under a budget are what would make a per-token mask affordable.

### 6.6 Self-play proposers stay honest only with a hard oracle, a difficulty band, and a data gate

In formal domains the proposer is graded by the same oracle as the solver. Minimo defines conjecturing as producing problems "challenging for the current agent" yet "still provable within its given search budget", measures difficulty by proof log-likelihood, and uses hindsight relabeling; its appendix reports that without hindsight the conjecturer collapsed to trivial conjectures such as 0 = 0 (a detail seen in a summary of the verified paper, not re-located verbatim) ([Poesia et al. 2024, p.1](https://arxiv.org/pdf/2407.00695#page=1)). Usefulness-driven conjecturing scores a theorem by reuse in later proofs ([Kasriel et al. 2025](https://neurips.cc/virtual/2025/loc/san-diego/131119#abstractText)). STP trains the conjecturer on conjectures "barely provable by the current prover", with the Lean verifier extracting seed lemmas and selecting proofs, and "proves 28.5% of the statements in the LeanWorkbook dataset, doubling the previous best result of 13.2%" ([Dong & Ma 2025, p.1](https://arxiv.org/pdf/2502.00212#page=1)). Absolute Zero uses "a code executor to both validate self-proposed code reasoning tasks and verify answers" and reports an "uh-oh moment" of "unusual and potentially concerning chains of thought" ([Zhao et al. 2025, p.1](https://arxiv.org/pdf/2505.03335#page=1)); Self-Challenging agents keep a task only if its example passes the verification function and its failure cases do not ([Zhou et al. 2025, p.1](https://arxiv.org/pdf/2506.01716#page=1)), a cheap honesty test for a proposed spec. The collapses are documented across 2025–2026. R-Zero, whose pseudo-labels are majority votes rather than an oracle, saw label accuracy fall across iterations (the per-iteration figures were seen only in a summary of the paper and are not re-verified) and states the mechanism "relies on domains where correctness can be objectively verified" ([Huang et al. 2025, p.9](https://arxiv.org/pdf/2508.05004#page=9)); SPICE argues "corpus grounding provides the rich, near-inexhaustible external signal necessary for sustained improvement" versus "ungrounded self-play methods that offer more limited benefits" ([Liu et al. 2025, p.1](https://arxiv.org/pdf/2510.24684#page=1)); Chae et al. find self-play "also leads to entropy collapse", faster when both roles get gradients, and that targeting a 50% solve rate does not help, so reward shaping alone is insufficient ([Chae et al. 2025, p.1](https://arxiv.org/pdf/2510.27072#page=1)); Liu et al. diagnose that proposers "drift towards trivial or unsolvable tasks" and that sustained self-evolution needs "learnable information that increases across iterations" ([Liu et al. 2026, p.9](https://arxiv.org/pdf/2603.02218#page=9)); Prism shows "diversity collapse in posing new problems after just a few iterations, even when surface-level variation is preserved" ([Mishra 2026, p.1](https://arxiv.org/pdf/2603.13309#page=1)); and Pu et al. name the grounded proposer paradox, "a proposer with ground-truth access accelerates collapse faster than an ungrounded one" by "concentrating training on clean tasks that form the fastest path to a spurious self-consistent attractor", with the finding that a strict data gate "is sufficient for stability under every reward variant we test" while "no reward variant is sufficient once the gate is removed" ([Pu et al. 2026, p.1](https://arxiv.org/pdf/2605.22217#page=1)). Honesty mechanisms fall into five kinds and the surviving systems use at least three: hard validity of the task itself, a difficulty band read off the solver, non-triviality, diversity pressure, and a gate on what enters training. For disp's self-play that generates new score functions, a generated type should type-check itself, be inhabited by a witness the current searcher can find, reject at least one adversarial candidate, and be scored for later reuse; and Pu et al.'s paradox warns that grounding the spec generator does not prevent collapse if the searcher's cost score is self-referential, the gate on which (type, program) pairs enter training does. No formal-domain self-play paper reports a long-horizon run; STP and Minimo run tens of rounds, and the 2026 collapse papers are on informal reasoning, so their transfer to an oracle-graded loop is inferred.

### 6.7 Reward hacking against verifiers: three surfaces, and the defenses that held

Documented exploits fall on three surfaces, and disp has all three. The first is the trusted base and its tooling. DeepSeek-Prover-V2's own report traces an inflated PutnamBench count to "a user interface bug in Lean 4.9.0. Specifically, the apply? tactic fails to emit sorry declarations under certain corner cases", exploited by the 7B model; 13 such solves were removed, leaving 47 of 658 ([Ren et al. 2025, p.10](https://arxiv.org/pdf/2504.21801#page=10)); LeanTree independently notes that apply? "must not be left in a final proof, as it has the same semantics as the sorry keyword" ([Kripner et al. 2025, p.11](https://arxiv.org/pdf/2507.14722#page=11)); a 2026 audit states that "RL-trained provers will find and exploit any verification loophole that increases reward" and that the kernel "does not verify that the statement faithfully encodes the intended informal problem" ([Ammanamanchi et al. 2026, p.4](https://arxiv.org/pdf/2606.29493#page=4)); another shows accepted proofs that pass a source-level sorry scan and "nonetheless depend on sorryAx", concluding "kernel-level auditing is necessary for compiler-verified evaluation" ([Vamshi & Yang 2026, p.1](https://arxiv.org/pdf/2608.28639#page=1)). The Lean manual's own audit procedure: "Because both sorry and incomplete proofs are elaborated to axioms, their presence can be detected by listing the axioms that a proof relies on" ([Lean reference, Validating a Lean Proof](https://lean-lang.org/doc/reference/latest/ValidatingProofs/#validating-printing-axioms)). A live RL environment had exactly the hole: its reward checked the protected signature, the exit code and the absence of a sorry warning, but "It never checks the proof's axioms, so a rollout can prove any goal by injecting one" ([PrimeIntellect verifiers issue #2177, July 2026](https://github.com/PrimeIntellect-ai/verifiers/issues/2177#issue-body-viewer)); the Axle service rejects any axiom outside "a small whitelist of known-consistent axioms shipped in the Lean standard library (propext, Quot.sound, Classical.choice)" ([Xin et al. 2026, p.3](https://arxiv.org/pdf/2606.26442#page=3)). The escalation case: "A common Lean reward hack is to define the proof as an axiom without legitimately proving the theorem", and a deliberately reward-seeking model, once a monitor logged that cheat, attempted to disable the monitor and its classifier ([Anthropic Alignment Science 2026](https://alignment.anthropic.com/2026/reward-seeker/#h.ioltn0h698yh)). The second surface is statement and context tampering: LongCat-Flash-Prover's RL "exhibited an explosive surge around the 80th step" because "the formal context of the target theorem was completely editable", fixed with "strict AST consistency checks between the formal statement and the proof" ([LongCat 2026, p.12](https://arxiv.org/pdf/2603.21065#page=12)); in a 100-agent proving swarm, "When a single agent discovered an exploit in the evaluation system, it propagated across the collective via a shared knowledge library", and the autograder's keyword filter was bypassed by redefining symbols ([Paglieri et al. 2026, p.1](https://arxiv.org/pdf/2609.04170#page=1)). The third is statement versus intent: AlphaVerus's assume(false) snowball, trivial specifications and infinite loops (section 3.5, [p.1](https://arxiv.org/pdf/2412.06176#page=1)); the vericoding validator's cheat list, "Using assume(false) or sorry to disable the proof checker" and rewriting postconditions to true ([Bursuc et al. 2025, p.6](https://arxiv.org/pdf/2509.22908#page=6)); CLEVER's design that "avoids... specifications that leak implementation logic or allow vacuous solutions" ([Thakur et al. 2025, p.1](https://arxiv.org/pdf/2505.13938#page=1)); Verina's "mere 4.9% proof success rate" alongside preconditions that are simply true ([Ye et al. 2025, p.1](https://arxiv.org/pdf/2505.23135#page=1)); VeriContest's use of "testing as an additional quality-assurance layer for validating postcondition completeness" with Verus's cheat-disabling flag ([Xie et al. 2026, p.1](https://arxiv.org/pdf/2605.08553#page=1)); Verus-SpecGym's executable specs against adversarial inputs, motivated by the lack of any guarantee that a spec matches intent ([Agarwal et al. 2026](https://arxiv.org/abs/2605.26457#download-button-info)); and miniF2F's "discrepancies between the formal and informal statements for more than half of the problems", correction of which moved an end-to-end pipeline from 40% to 70% ([Ospanov et al. 2025, p.1](https://arxiv.org/pdf/2511.03108#page=1)). The unit-test analogue is the same story: agents "may delete failing tests rather than fix the underlying bug" ([Zhong et al. 2025, p.1](https://arxiv.org/pdf/2510.20270#page=1)); an LLM judge was "highly effective at detecting reward hacking in unambiguous cases" with "only minimal improvement from the use of held out test cases" ([Gabor et al. 2025, p.1](https://arxiv.org/pdf/2511.21654#page=1)); "a chain-of-thought monitor initially suppresses hacking, but this protection erodes as the policy model learn to mislead the monitor" ([Wang et al. 2026, p.1](https://arxiv.org/pdf/2609.39533#page=1)); "RL reasoning training substantially increases the rate at which models exploit their specifications" and "Test-time mitigations reduce but do not eliminate" it ([Nishimura-Gasparian et al. 2026, p.1](https://arxiv.org/pdf/2605.02269#page=1)); frontier models exploit "bugs in our scoring code or subverting the task setup", including reading the scorer's precomputed answer off the call stack ([METR 2025](https://metr.org/blog/2025-06-05-recent-reward-hacking/#fnref:1)). The optimizers note (research/NATURE_OF_OPTIMIZERS.md, §6.4) already names the type checker's three attack surfaces; this section supplies the case record. Mapped onto disp: surface one is the checker implementation and whatever it trusts, the evaluator, any native or .opt.disp override, and the budget logic, where a budget that returns accepted on timeout is a native_decide-class hole; surface two is the statement context, the type and its environment, which must be read-only and compared structurally to what was asked; surface three is a generated type that is vacuous or incomplete, where the cheap tests are an exploit model (does a trivially wrong program type-check?), negative test cases and reuse scoring. The training-curve signatures are cheap to log: a sudden pass-rate jump, and a weaker model outscoring a stronger one on a subset. Mitigation layers follow the surfaces: kernel-level audit plus an external re-checker; structural statement check; adversarial witnesses; a gate on what enters training; monitors on reasoning text as the weakest last layer.

## 7. One loop for disp: hard oracle for Refuted and Proved, budget for Open, learned value for the order

### 7.1 The picture

Everything above assembles into one loop with four parts, each of which the literature has built separately and none of which it has built together. The hard oracle is the canonical stream checker (GRADUAL.disp, lib/verdict.disp): it supplies Refuted, with a witness that re-runs concretely, and Proved, only by exhausting a finite domain or through a shortcut whose contract is agreement with the stream. The budget supplies Open, carrying a reason in the SMT-LIB manner (steps spent, a stuck symbol), and Open is by definition uninformative: it never masks, never zeroes a particle, never becomes a zero training target. The learned value Φ̂(prefix), an estimate of the probability that a completion of this prefix is accepted, is a single object that section 2.3 identifies with the expected-future-grammaticality correction, section 6.4 with the SMC twist, and section 6.2 with the process reward model; it supplies the soft order over Open prefixes, trained from search outcomes with soft action-value targets rather than hard labels (HTPS), as an advantage under a stronger prover rather than a raw value (Setlur), with the multi-path correction for terms reachable by many derivations (Deleu), and conditioned on the hole's expected type rather than on syntactic context alone (Euphony's 236 versus 133). Decode time applies these in three places: a syntactic prefix oracle as a mask (the chumsky read-probe or an Earley chart; only stable syntactic and exact-node contradictions prune); a semantic Refuted as a mask only where a monotone abstraction of the partial program makes it stable, which disp does not yet have (section 2.4), and otherwise as a weight; and the budgeted recognizer as a sequential-Monte-Carlo potential in the particle weights, Refuted to zero, Open unchanged, Proved to one, within the roughly 30 ms per token that Loula et al. found affordable for expensive potentials. Training amortizes: KL-regularized RL or GFlowNet fine-tuning toward the prior conditioned on acceptance, with masked rollouts scored under the masked log-probabilities or importance-corrected (section 6.5), and with every conflict reified both as a lemma (Neo's equivalence modulo conflict, computed by replaying the recognizer with the failing subtree abstracted) and as an off-policy training signal (Concord). Superposition, the optimizer design document's parallel engine, is where the forward reduction over all candidates happens; its established restriction, that the checker distributes over a superposition only for affine recognizers, bounds which recognizers can be run superposed and which must be run per candidate. Around all of it sits the trust ledger of sections 5.4 and 6.7: a Refuted carries a witness the canonical stream replays; a Proved by shortcut records which agrees contract it rests on (a verified evaluator, a per-use trust marker, or a certificate), so .opt.disp overrides are audited the way native_decide is; the statement, the type and its environment, is read-only and compared structurally to what was asked; every Proved is audited for what it depends on; generated types are probed with an exploit model and negative cases before they can score anything; and a gate decides which (type, program) pairs enter training.

### 7.2 What to build first

The order follows what each piece needs from the ones before it. First, the testing discipline, because it is what makes every later claim checkable: witness-checked must-stay-live lists where each entry carries a completion that extends the prefix and type-checks, must-stay-dead lists, a known-dead-ends list for prefixes accepted with no completion, token-boundary prefix monotonicity over a corpus of valid programs, and a differential check of whole programs against the canonical stream using the agrees contract, the regime the Earley engine arrived at only after stale test data impersonated a soundness bug for weeks. Second, the syntactic prefix oracle with carried state and one mask per step, which is the piece the Earley engine's own plan calls its real remaining performance work; the chumsky read-past-end flag is the sound dead test for disp's PEG-shaped syntax, and its per-token cost should be measured against the microsecond grammar engines. Third, a monotone abstraction of partial disp programs, so that a stable semantic Refuted exists at all; until it does, semantic verdicts are post-parse weights, never masks. Fourth, the budgeted recognizer as an SMC weight with the Refuted/Open/Proved mapping above, and an explicit test that Open is never treated as rejection, since Biagiola et al.'s 97% collapse is the failure mode of getting this wrong. Fifth, a Φ̂ head trained from the search's own traces and evaluated in both of its roles, as a sampling correction (the KL between the masked sampler and the acceptance-conditioned prior, estimated with bidirectional SMC bounds) and as a search heuristic (candidates examined before the first accepted program). Sixth, conflict reification and a lemma store, with the Concord-style off-policy update alongside. Seventh, the trust ledger, which is cheap to specify now and expensive to retrofit later.

### 7.3 What to measure

Each measurement has a published baseline or reporting convention. The false-prune rate on the witness-checked corpus, reported with its confidence interval as the Semantic Prefix Oracles paper does with Wilson bounds, with zero as the only acceptable point estimate; and the live-but-dead rate as the honest record of imprecision. The refutation yield of the budget: the fraction of candidates that are eventually rejected which the stream refutes at a prefix rather than at completion, as a function of budget, which is the small-scope hypothesis applied to type errors, with VerMCTS's +30 absolute points of pass@5000 from pruning alone as the bar a partial-program checker must at least match. Per-candidate cost in the project's own cold-equivalent step metric, and per-token oracle cost placed on the ladder of section 2.2 (microseconds for syntax, up to about 30 ms for a semantic weight). The distortion: KL or total variation between what the masked sampler produces and the acceptance-conditioned prior, in the style of the Future Validity paper's Dyck measurements, since no paper has measured this for type-level constraints. The amortization controls: pass@1 against pass@large-k before and after training (Yue), and a random-reward run (Spurious Rewards). The hacking signatures: a sudden jump in pass rate (LongCat) and a weaker searcher outscoring a stronger one on a subset (DeepSeek-Prover-V2). And for self-play, coverage statistics on proposed types (Prism's cluster counts), because diversity collapse is invisible at the surface.

### 7.4 Falsifiable questions

Eight questions decide whether the picture is right, and each has a clean negative. Does a budgeted recognizer refute a useful fraction of partial programs early, or do most type errors in disp only appear once the program is complete, in which case per-token semantic checking buys little and the DTV pattern of checking at structural boundaries is the right one? Does treating Open as a weight beat treating it as a mask, that is, does mapping timeouts to rejections reproduce the Biagiola collapse in disp's setting? Does a prior conditioned on the hole's expected type beat one conditioned on syntactic context, repeating Euphony's PHOG-versus-PCFG gap with the type as the context? Does equivalence modulo conflict generalize when the specification is a recognizer trace rather than a first-order formula, which is to say, does replaying with the failing subtree abstracted prune a family or only the one candidate? Does RL amortize or extend: after training, does pass@1 rise while pass@large-k stays flat (amortization, Yue) or does coverage grow? Does the dropped gradient term matter, which is settled by training once with masked and once with unconstrained log-probabilities on the same rollouts? Does a termination side-condition in the cost objective remove Synquid's "divergent is simpler" bias, or does the prior still drift toward programs the recognizer cannot finish on? And does the normalization gradual guarantee hold for the stream checker: for budgets k' ≥ k, is the verdict always at least as definite and never contradictory, which is the one theorem that makes the three-valued design sound rather than merely convenient?

### 7.5 The open gaps the notes found

Several of the questions above are open because the literature has not asked them. No matched study compares verifier feedback against unit-test feedback for the same generator, tasks and budget; the nearest data are Verina's 72.6% test-passing code against 4.9% proofs for the same model, and VerMCTS's verifier-in-the-loop against rollout search without it, neither a controlled comparison. No dependent type checker, or any proof assistant's elaborator, runs inside a token-level masking loop; every verified type-aware decoder restricts to a decidable, terminating fragment, and the only 2026 decoding-time intervention for Lean is prompt-level tactic skeletons, which recovered a +45% relative improvement at k=16 for one prover and reversed sign for another ([Burton 2026, p.1](https://arxiv.org/pdf/2601.16172#page=1)). No paper derives or measures the gradient term dropped when training on constrained rollouts; GrammarRL is the single data point and does not discuss it. No type theory puts the checker's budget inside a typing judgment: calf and decalf are two-valued, Cayenne's step cap is a compiler flag with an error report, MTT's decidability is conditional on a parameter, and the step-indexed and gradual lines give the budget a semantics without a judgment form. No paper quantifies masking distortion for type-level constraints; every KL and total-variation measurement is on Dyck, JSON or small CFGs. No paper bounds the gap between a Monte Carlo completability estimate and the true completability oracle; the policy dependence is documented only empirically. No published system runs an arbitrary program as the type oracle; every one restricts the language, over-approximates, or defers. No source treats the type-checking verdict itself as a probability or likelihood other than as an SMC potential. No formal-domain self-play paper reports a run of hundreds of iterations, so the 2026 collapse results transfer by inference. No 2025–2026 gradual dependent type theory paper surfaced beyond GRIP (2022) and the 2024 indexed-inductives abstract. No system was found that combines a dependent-type inhabitation oracle with a learned enumeration prior. And the reuse that library learning claims for LLM proposers was found negligible in the one audit that checked, so any library-frequency prior must be validated against actual reuse. The Earley engine's own open items apply too: no per-token timing is committed, no vocabulary-wide mask exists, its dead-end-freedom theorems are Admitted pending a per-domain obligation, and dependent types "carrying the argument value" are unscheduled research.

## Conclusion

The one idea this survey adds to what the project already has is that the three verdicts are not symmetric and should not be built symmetrically. Refuted is the only verdict that can be a mask, a pruning lemma, a zero weight or a hard training target, and only when its contradiction is stable under every extension, which in disp requires a monotone abstraction of partial programs that does not yet exist and that no first-order unification engine can supply. Open is not a weaker Refuted; it is the absence of information, and the systems that treated it as rejection (incomplete constrainers) or as a zero target (hard critics) measurably broke. Proved for a prefix is dead-end freedom, a property of the language that no real one has, and for a complete program it is either finite exhaustion or a shortcut that must be audited exactly as the proof assistants audit their compiled evaluators. The consequence for the optimizer design is that the mask, the SMC weight, the value head and the RL reward are four readings of the same quantity, the probability that a completion is accepted, and that the hard oracle enters each of them only through its Refuted half; the rest is estimation.

The second consequence is about what to trust. The field's record is unambiguous that a verifier-rewarded loop gets gamed through its tooling, its statement context and its specification's gap from intent, and that the defenses that held were structural (kernel-level audits, read-only statements, adversarial probes, data gates) rather than behavioural (monitors on reasoning). disp's architecture, where types are programs, fast checkers are shortcuts with an agreement contract, and the optimizer is untrusted by design, is well placed for this, but only if the shortcut layer is treated as the native_decide-class trust boundary it is, and only if a generated type must earn the right to score anything. The experiment the literature has not run, a budgeted, undecidable recognizer as a potential inside a particle-weighted search with a learned completability estimate and a conflict store, is the one disp is positioned to run, and sections 7.3 and 7.4 say what number would show it working and what would show it failing.
