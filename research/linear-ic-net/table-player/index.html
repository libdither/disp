The adds

Every add in the prelude, named for the kind of program it is, the shape of its numbers and the way it adds. Click one to play it.

linear uses every variable, so no eraser ever appears, and copies only where a variable is used twice. ordinary is the usual way: a fixpoint or a test, and what is not picked is erased. reversible is linear and also hands the first number back, so a subtract can undo the add: an add alone forgets, since 1 + 2 and 2 + 1 give one sum.

What you are looking at

A λ-calculus run as an interaction net. Each shape is an agent, each line a wire. Two agents joined by their main ports (a bright wire, in the colour of what the rewrite will do) are about to rewrite; nothing else can happen. The program hangs from the root (the ring at the top), and its answer ends up there.

Functions are one agent. When a program loads, every λ in it becomes a definition in a fixed list. A function in the net is one agent (λ on a tile) that names its definition, labelled beside it with the definition's name or number, and holds the values it captures on its pins below, one pin each. Copying or erasing a function is one rewrite.

A call is a running application (pink @) meeting a function. In one rewrite the body is laid out from the definition, already running: the argument goes to the uses of the variable, and the captured values to theirs. A layout can make dozens of agents at once; they grow out together, and the caption says how many. An opened function (Λ) lays its body out as code instead.

Tables. keep[e1 | … | e6] is a table (teal), a value with six slots, one for each kind of value: function, opened function, application, variable, ρ, table. Its six slot pins have their own colours: Applied to a value, a table becomes a reading table (cyan) facing it. When the value arrives, the slot for its kind is copied: one copy goes back into a rebuilt table, the other is applied to that table and then to the value's parts. A function comes opened, an opened function closed, an application as its two parts. The table is the only reader, and it is its own loop: a slot that reads again applies the table it is handed.

Code is frozen. Grey shapes are code: applications (small disks) and uses of variables (dots). A thaw (green arrow) walks down code and turns each application into a running one. It stops at a function: its body stays in the definition until the function is called.

Copying happens only where a value is used twice: a split (thin violet Y) sits on its wire. When the value arrives, copiers (thick Y, one colour per copy) walk through it one agent at a time. Two copies under way at once keep their own colours. Erasing happens only where a value is not used: an eraser (red ×) walks through it.

Structures. Code that hangs together sits on one faint band: one value, or one stretch of code. Bands keep apart, and what is running, copying or erasing stands between them. A band's label is the name of the part it comes from, or else the start of its term. A number carries a green tag that says which number it is, wherever it is and however it was built; its bits are the functions b0 and b1.

Terms. Point at an agent to read the subnet under it as a term, and see the whole net as one above. A name stands for a part that is whole or a function whose definition has one. In a term, ▸c is a thaw on code c, f @ a an application that is running, ‹v› a value a variable stands for, ⧉n⟨v⟩ a side of copy n that has still to pass through v, and read⟨v⟩ a table reading v.

Named parts. Named code that is not a function (the table size, err, …) that nothing is acting on is drawn as its name on a pill. Click a pill to open it, and the tag of an opened part to fold it again. A part opens by itself when something reaches it, and a table being read keeps its name through the reading.

Ports. Every port is a pin on its own side of the icon, and wires join pin tips. The main port's pin ends in a white dot. Only main ports meet: a rewrite happens where two main ports are wired together, and it rewires what was on the side ports. An icon turns, and flips left for right, to face its pins toward what they are wired to; its letter stays upright.

Physical. Tick it and play: the two agents of every pair that can fire are drawn together, and the pair rewrites when its main pins touch. What is close goes first, and what must cross the net goes later. The answer and the number of rewrites are the same as in any other order.

Drag an agent to move it; the layout gives way around it and settles again when you let go. Drag empty space to move the view, and scroll to zoom. The shapes named here are the suggested icons; others can be chosen.

Linear programs (linear_unary_add, linear_list_add) use every variable, so no eraser ever appears, and the only copies are the ones the program asks for: a number is its own loop, each successor copies the step once, and zero hands the last copy back. Try linear_unary_add 40u 2u or linear_list_add 1000 2000, with numbers of any size: the answer holds the sum first, then what is handed back.

Numbers as trees. 1014t is a tree of bits: pairs of pairs with a bit at each leaf, the low half on the left, and beside it the depth as a loop. linear_tree_add 1014t 2413t adds two of them with nothing erased, and hands back a tree: the adder for a tree is two adders for its halves, and the depth says how often to halve. ordinary_tree_add adds the same trees the usual way, testing each bit and dropping the arm not taken. linear_tree_add_parallel adds them in parallel and still erases nothing: every part of a tree works out its carry out for both carries in at once, and the carry then goes down.

Reversible. A linear add erases nothing and still forgets: many pairs of numbers give one sum. reversible_tree_add a b hands back a and the sum, and reversible_tree_sub a s hands back a and s − a, so each undoes the other: reversible_tree_add 1014t 2413t reversible_tree_sub ends with 1014 and 2413 again. Only the answers can be had back this way. A rewrite of the net cannot be undone: the ◀ buttons go back to moments the page kept.

Order does not matter. Fire pairs in any order you like, or pick another order under the bar: the answer is the same, and so is the number of rewrites. A pair you fire replaces what was planned from that moment; the rest of the run is planned again, and its length does not change.

Writing programs

\x y. body is a function, ^x. body an opened one (so (^d. p) u is the code of p), f a applies, keep[a | b | c | d | e | f] is a table and ρ a primitive value. Every name must be bound by a function or defined: name := term; … defines names first. A number is written with its form after its digits. The linear ones: 5u is unary, 5 a list of bits and 5t a tree of bits. The ordinary ones: 5s is unary and 5c a list of bits. For the add whose two numbers have different shapes, 5a is a number whose cells pick an arm and 5p a chain of pairs. Every list of bits in a program gets one bit more than the largest needs, so a sum of two fits, and every tree number the fewest levels that hold as much. A value that is such a number is shown as one, and a tree of bits with no depth beside it as {n|leaves}. These are defined already:

zero, suc, add, true, false, Z, kindOf, size, no, err, close, open, interp, and the adds: linear_unary_add, ordinary_unary_add, linear_list_add, linear_list_add_two_shapes, ordinary_list_add, linear_tree_add, ordinary_tree_add, linear_tree_add_parallel, ordinary_tree_add_parallel, reversible_tree_add, reversible_tree_sub, reversible_tree_add_parallel, reversible_tree_sub_parallel, with their parts
